# 工厂默认打印与库存扫码

更新：2026-09-11。打印模板随 `process_simplification` 安装和迁移自动注册，正常发布时无需人工复制表头或逐张配置。仅展示已保存的单据数据；打印、搜索和扫码均不提交出入库、不改变派工、不修改金额或库存。

## 默认模板

| DocType | 默认格式 | 业务范围 |
| --- | --- | --- |
| Purchase Order | 工厂采购订单 | 采购明细、到货日期、价格、税费折扣、原单总额与大写 |
| Job Card | 工厂生产任务单 | 生产物料、工序、任务数量、工作站、用料与签字 |
| Purchase Receipt | 工厂采购收退货单 | 采购入库、供应商退货，接收与拒收数量分别显示 |
| Stock Entry | 工厂库存作业单 | 材料出入库、调拨、生产发料、耗料、完工入库等；按 purpose 显示标题 |
| Delivery Note | 工厂销售出退货单 | 销售出库、客户退货入库 |

统一黑白公司表头、右上角 28 mm 内部二维码、标题和状态、关键信息区、明细与签字。公司资料按当前单据所属 Company 读取，初始化后维护公司资料即可。单位不同的数量不合并汇总；库存凭证按每行来源仓库和目标仓库展示方向。单位换算显示保存的 `stock_qty` / `transfer_qty`；退货保留原有负号。库存凭证不显示内部估值与会计配置字段。

公共正文组件为 `templates/print/factory_sheet.html`，已有 Job Card 专用正文继续保留。表头和受管格式记录使用 Jinja include 引用应用内文件，今后修改模板随代码升级生效。按内容哈希确认的旧受管表头会迁移到 include；管理员自行改过的表头保留。

## 安装与默认选择

`after_install` / `after_migrate` 顺序为初始化持久系统标识、补建表头、执行 `ensure_factory_print_formats()`。格式不存在时创建；默认为空或 Standard 时设置相应工厂格式。采购与销售出库的原生 Standard / with Item Image 格式，只有记录仍为原生 `standard=Yes` 才替换默认。

以下情况保留客户配置：已有其他默认格式，同名格式被改写、所属 DocType 不匹配或被禁用，已有自定义表头，以及用户在打印时明确关闭表头。不会将客户配置当作受管模板覆盖。

Desk 预览默认中文，五类单据原本使用空表头或原生 Company Letterhead / Grey 时自动选择工厂表头。服务端 `pdf_body_html` hook 对本应用受管格式应用相同选择，并同时切换页眉、页脚；后台 `frappe.get_print` 不传格式和表头也获得对应默认版式。其他打印格式交给原生渲染，不修改其 HTML。

## 库存扫码与搜索

内部码保留 `HSERP|1|系统标识|类型|编码单号` 协议，新增 `purchase-receipt`、`stock-entry`、`delivery-note`；原采购和任务单内部码继续有效，不因换域名失效。

库存扫码先校验当前站点标识，再读取准确类型的单据并执行原生 `read` 权限检查，成功打开原表单。不存在和不可读使用相同提示，不披露隐藏单据。扫码不执行入库、发料、出库或自动提交。

手动搜索继续先显示候选，即使只匹配一条也需点击；每次点击重新校验权限。新类型通过原生 `get_list` 搜索单号、供应商 / 客户、库存作业类型 / 工单，不绕过公司或列表权限。结果全局最多 20 条，完整单号优先；库存暂不按明细物料名检索。Job Card 的本人派工定位规则和管理账号点击搜索结果的规则保持原样。
