## 回归覆盖

新增 test_batch_safety_stock_integration.py 共 9 项真实数据库用例，覆盖：

1. 只填写安全库存不自动创建申请；关闭自动再订货也不创建申请。
2. 新批号自动创建、出库自动沿用实际批号、取消出入库后余额恢复。
3. 原生再订货申请进入恒算缺料采购/供应商分配队列，申请量计入预期库存，重复任务不重建，取消后恢复补货。
4. 过期/禁用批次不能抑制补货；正常批次库存保持正常计算。
5. 销售需求及指定批次预留不重复扣减。
6. 仓库组汇总使用各子仓可用批次，补货落在配置目标仓库。
7. 普通物料仍按原生小于等于阈值触发，无批次计算依赖。
8. 自动申请转采购订单、部分收货自动编号、供应商退货沿用原批次；实物库存与采购在途衔接正确，取消后数量恢复。
9. 生产计划“计入安全库存”关闭/开启仍分别按原有 3/8 件需求计算，不改变计划与共享物料逻辑。

现有全应用回归还覆盖销售开单、采购分配、发退料、发货退货、制造/半成品/补产、报工审核、异常处理、工资、岗位权限、打印和页面刷新；具体模块与断言见测试源码，不能据此宣称所有原生 ERPNext 组合均已验收。

### 本地实时环境修复

原 8016 独立 Web 服务缺少同源 socket 路由，本机浏览器出现 xhr poll error；独立 socket 进程也无法用 localhost 回连另一容器的 Web。新建仅绑定 127.0.0.1:8017 的隔离代理，把 socket 与 Web 放到同一验收入口，并使本次专用 socket 进程与 Web 共享网络命名空间。只在专用配置中指定本地回连地址，保留原生会话、命名空间和来源校验，未修改 Frappe 核心或共享站点配置。

浏览器有些同源轮询请求不带 Origin；代理仅在该头缺失时补入当前源，已有 Origin 原样传递。最终新页面未出现连接错误。两张库存单分别在另一页提交后，库房待办无需手动刷新即自动移除；第二张提交后本页 0 张，实时更新得到实际页面验证。

复查入口：http://localhost:8017。仅为本地隔离站，不是正式地址。新增容器 hs-pre-delivery-proxy-20260915、hs-pre-delivery-socket-20260915；本地配置保存在本次日志目录。修改标准 Page 的脚本后，应执行正常构建与缓存刷新；仅刷新网页可能继续使用 Frappe 本地缓存的旧脚本。
