# 恒算 ERP：prod 部署后与工厂开工前初始化指南

对应[工厂使用手册第 01 页](https://rcnz1aofm14f.feishu.cn/wiki/GcgAwDyOEilXvokKo5tcskHDnac)。修订日期：2026-09-22；第 1–10 节已同步原飞书文档并回读核对，本轮更新第 3.4 节“可选半成品仓”，库存预留开关说明保留。[直接打开初始化章节](https://rcnz1aofm14f.feishu.cn/docx/IlmWdYePRo9yc8xll2CcffpwnJg#doxcnslUzbRot454Ym3Ih0QR2ih)。本地第 11 节另附技术验收证据。

## 使用顺序与适用版本

适用：刚部署的恒算 ERP、准备正式使用的工厂。本指南在原有内容上补充了本轮隔离站开用步骤；未修改 prod 设置或业务数据。文中“修改名称”“默认半成品仓”等新增能力已纳入本地候选版本，尚未发布 prod，使用前由实施人员核对实际版本。以下设置与操作要求需由管理员逐项完成，不能据此认为生产已经配置完成；原截图保留其拍摄日期。

顺序：公司和系统 → 仓库及默认值 → 单位、物料、往来单位 → 工作站、工序、BOM → 用户、员工、岗位、工价 → 期初库存 → 小订单验收 → 正式开工。管理员账号先用于配置，其余岗位在试运行前准备好。

## 1. 手机号、用户名和员工姓名，怎样用于登录

入口：全局搜索 System Settings，打开原生“系统设置”。它和恒算 ERP 菜单里的“系统设置”（Process Simplification Settings）是两张不同的设置表。登录开关在原生 System Settings。

1. 勾选 Allow Login using Mobile Number（允许使用手机号登录）和 Allow Login using User Name（允许使用用户名登录），保存。
2. 打开 User（用户），为每人维护唯一的 Username（用户名）和 Mobile No（手机号）。不要只填 Phone（电话）或员工档案里的联系方式。
3. 为账号分配合适岗位，确认是 System User（系统用户）且已启用；由管理员按本厂方式设置初始密码并安全交给本人。
4. 打开 Employee（员工），填写姓名、性别、出生日期、入职日期、公司等页面必填项，状态为 Active（在职），将 User ID（用户）关联到本人的账号。一个工人账号只能对应一个在职员工；再到“权限管理／岗位与范围”设置公司、仓库及员工范围。
5. 保存 User 后重新打开，确认用户名、手机号和岗位确实保存。退出后分别用“手机号＋密码”“用户名＋密码”验证，确认进入同一个账号和正确岗位首页。验证应由本人或授权管理员完成；只在新建表单里输入过登录名不算验证成功。

当前原生界面的退出入口位于侧栏最上方工作区名称的下拉菜单，选择 Logout（退出）；底部头像通常打开个人用户资料。共用设备切换岗位要先退出，再用下一位员工本人的账号登录。

| 字段 | 示例／用途 | 要点 |
| --- | --- | --- |
| 显示姓名 | 张三 | 用来显示人名，不等于登录名 |
| Username | zhangsan01 或工号 gs001 | 唯一；保存后确认没有因重名被清空 |
| Mobile No | 员工本人手机号 | 每人唯一；统一保存格式，登录时按保存格式填写 |
| Email | 工厂为该员工分配的邮箱地址／受控邮箱格式账号标识 | 原生 User 仍要求填写；员工日常可以用手机号或用户名登录 |
| Employee → User ID | 关联上面的 User | 用于本人任务、报工与工资归属，不是另建一套登录密码 |

如果一定要输入“张三”登录，需要把 User 的 Username 明确设为“张三”且唯一，再实测；只填员工姓名不会自动保证姓名登录。同名员工应改用不同工号或姓名加编号，日常建议手机号或工号。

这两个开关仍使用账号密码，不会自动提供短信验证码登录。没有真实收件邮箱时，不依赖欢迎邮件或“忘记密码”邮件：新建用户时按需取消 Send Welcome Email，由管理员管理初始密码及后续重置。不要启用 Disable Username/Password Login，除非已经另行完成并验证替代登录方式。

## 2. 公司和部署后的常用设置

| 打开哪里 | 怎样配置 | 验收点 |
| --- | --- | --- |
| Company ＋ Global Defaults | 确认正式公司、公司简称、币种 CNY；全局默认公司和各账号默认公司一致 | 新单据默认带出正确公司 |
| Company／Fiscal Year | 核对业务日期覆盖的会计年度、成本中心和需要的库存、存货差异等账户 | 库房正式过账前由财务确认；只建物料不能替代这些默认值 |
| System Settings／用户语言 | 中文；时区核对为 Asia/Shanghai；日期、时间、数量精度按现场习惯 | 时间与工厂一致；本版本系统时区字段只读，若错误交实施人员用原生维护方式处理 |
| System Settings → Session Expiry | 根据个人设备或共用设备设定空闲退出时间，例如 08:00 表示空闲 8 小时 | 用真实手机核对重登体验；共用终端交班要退出 |
| 恒算 ERP 系统设置 → 角色默认首页 | 启用按角色进入默认首页；工人→我的任务，库房→库房工作台，主管→生产计划中心 | 多角色按表格从上到下匹配；首页配置不会增加业务权限 |
| 部署运维 | 确认 HTTPS、后台队列、调度器；配置自动完整备份、异地保存和失败告警 | 检查最近一次成功备份，完成一次隔离恢复；仅有备份文件不等于已证明能恢复 |

每人独立账号；管理员账号由实施／系统负责人保管。员工换岗时同步调整权限和接收通知的责任，离职时停用账号。不要为了看见一个按钮直接授予全部管理权限。

## 3. 仓库必须建，还要指定默认去向

先建本公司启用的末级仓库：Warehouse 的“是组／Is Group”不勾选。汇总仓只用于归类，不能作为实际收发仓。可沿用初始化已创建的合适仓库，避免再建一套同用途仓库。

| 仓库 | 放什么 | 在哪里关联 |
| --- | --- | --- |
| 原料仓 | 采购合格原料、可继续使用的好料 | Stock Settings → Default Warehouse；物料公司默认值和实际单据也需核对 |
| 在制品仓（WIP） | 已发到车间但尚未完成耗用／入库的生产物料 | Company → Default WIP Warehouse |
| 成品仓 | 已完工并由库房入账的可发货产品 | Company → Default Finished Goods Warehouse（default_fg_warehouse）；成品物料的公司默认仓也核对为成品仓 |
| 半成品仓（可选） | 独立自制、完工入库后等待后续加工或装配的半成品 | 候选版本：Company → 默认半成品仓；留空沿用原料来源仓，详见第 3.4 节 |
| 待检隔离仓 | 存在质量问题、等待判定的物料 | Company → 生产异常待检隔离仓 |
| 报废仓 | 已确认报废、需单独管理的物料 | Company → Default Scrap Warehouse；工单另设报废仓时优先用工单值 |
| 待返工仓 | 已判定需返工、尚未完成返工的物料 | Company → 待返工仓；返工还要有效 BOM 和返工工单 |

前三类是正常生产主链必备；待检和报废建议在正式开工前建好并配置，涉及返工时同时准备待返工仓。自制半成品若独立存放和收发，再按实际增加半成品仓，不需要为了“完整”把每个车间都建一套仓库。

本版本没有供该流程使用的 Company.default_warehouse；原料默认仓在 Stock Settings，在制品／成品默认仓在 Company。建了异常仓还须填入公司的对应字段。待检、报废、返工仓应按用途独立，不使用正常原料仓或 WIP 仓代替。好料退回原发料来源仓，质量问题料进待检隔离仓。

### 3.1 库存预留：两个开关分别怎么设置

| 库存设置里的选项 | 本次初始化建议 | 实际作用 |
| --- | --- | --- |
| Enable stock reservation（启用库存预留） | 开启（ON）并保存；重新进入确认仍开启 | 允许为订单、工单等保留数量；恒算流程的初始化检查要求启用。仅开启这个开关不会立即把所有库存分出去。 |
| Auto reserve stock（自动预留库存） | 初期关闭（OFF）；重新进入确认仍关闭 | 开启后，新建销售订单、工单、生产计划会默认启用预留，提交时按原生规则执行；会改变库存占用时机。 |
| Allow partial reservation（允许部分预留） | 开启预留后如出现，可保持开启 | 订单要 100 件、当前只有 40 件时，可先预留可用的 40 件，余量继续采购或生产。 |
| Allow Negative Stock（允许负库存） | 关闭 | 本版本库存预留与允许负库存不能同时启用；未收货或未录期初应补齐真实业务记录。 |

“启用库存预留”和“自动预留库存”不是同一个开关。关闭自动预留后，工作台按业务动作创建预留的能力仍在；预留不会让货物发生出入库。初期先确认订单分配和数量，再考虑是否改成默认自动预留。首单还要核对预留属于哪张订单、哪个仓库及多少数量，并在交付后检查剩余占用；开关已开不等于整条订单已跑通。

Auto reserve Serial and Batch Nos（自动预留序列号／批次）是另一项设置：它决定预留时是否提前指定批次，不等于是否自动为订单预留库存；按第 09 页批次操作卡配置。自动补货也独立设置，应先维护补货点、补货量、仓库和采购责任人，再验证真实队列与接收通知的人。

### 3.2 默认的在途物料仓，现在需要用吗

“在途物料”是公司初始化时可能创建的 Transit 类型仓库，不是正常生产必须配置的仓库。单厂直接收货、领料、完工入库时，可以保留但暂不使用，也不用把它填成默认原料仓、在制品仓或成品仓。

| 当前仓库名称示例 | 建议用途／设置 |
| --- | --- |
| 仓库 - 智 | 可作为原料仓；Stock Settings → Default Warehouse |
| 进行中 - 智 | 在制品仓；Company → Default WIP Warehouse |
| 成品 - 智 | 成品仓；Company → Default Finished Goods Warehouse |
| 在途物料 - 智 | 跨仓运输需要分别确认发出与收货时使用；目前可闲置 |

在途仓适用于“两步调拨”：A 厂原料仓 → 在途物料仓 → B 厂原料仓。A 厂已发出、B 厂尚未收到时，数量留在在途仓；B 厂收货确认后再进入目标仓。原生操作使用 Material Transfer（物料调拨）的 Add to Transit（加入在途）及后续接收流程。

供应商已接单但尚未收货的“采购在途”，由采购订单及未收货数量反映，不要为了显示在途而提前把货录入在途仓。采购到货后按实际收货提交到原料仓；生产领料进入的是在制品仓，不能用在途仓代替。

### 3.3 把默认仓库改成工厂容易理解的名称

2026-09-17 发布版本的仓库表单保存后隐藏名称字段，普通界面没有可用的通用重命名入口。本次候选版本新增了“修改名称”按钮，并处理返回仓库树时仍显示旧名的问题。**下面的新入口仅适用于已安装该修复的版本；本次隔离站验证不代表 prod 已更新。**若当前 prod 没有按钮，先让实施人员核对版本和账号权限，不要通过删除重建仓库来改名。

管理员操作：

1. 列出旧名与新名，例如“仓库 - 智 → 原料仓 - 智”“进行中 - 智 → 在制品仓 - 智”“成品 - 智 → 成品仓 - 智”。确认目标名称尚未被同公司其他仓库使用。
2. 以 Administrator，或同时具有 System Manager 和目标仓库修改权限的账号，打开具体仓库表单；先保存其他未保存修改。普通库房、物料管理员或老板业务角色不会因此获得改名权。
3. 点击“修改名称”，只填业务名称，例如“原料仓”，再点“保存新名称”；公司后缀会保留。不能借此更换公司、修改公司根仓或合并两个仓库。
4. 成功后核对表单标题及仓库名称，再返回仓库树，确认新名称出现、旧名称消失。
5. 回查库存设置的原料默认仓、公司在制品／成品默认仓、物料公司默认仓和已有用户权限。存在历史库存时，额外核对改名前后的库存数量和原单链接。

删除时提示“与用户权限限制关联，无法删除”，属于引用保护。改名字应保留现有仓库及其关系，无需先删用户权限限制，也不要直接改数据库。受限管理员同样只能修改其授权范围内的仓库。

隔离站已实际验证“修改名称”后返回已打开的仓库树能够显示新名；带库存及权限关联的检查另有集成证据。具体版本、操作记录与未验范围见文末验收记录，不能把两类证据合并为“prod 带库存改名已通过”。

参考：[ERPNext 库存预留](https://docs.frappe.io/erpnext/stock-reservation)、[原生在途调拨](https://docs.frappe.io/erpnext/stock-entry)、[通用重命名说明](https://docs.frappe.io/erpnext/renaming-documents)。通用重命名说明以具体站点允许改名且账号有写权限为前提。

### 3.4 可选半成品仓：按工厂实际收发方式启用

如果半成品会独立完工入库、存放备货，再分次领去后续加工或装配，建议规划独立半成品仓。如果只是同一工单内从一道工序流到下一道工序，不单独入库、盘点和领料，先用在制品仓即可。判断依据是实际收发和库存管理方式，不是工序数量。

| 仓库 | 对应的业务状态 | 例子 |
| --- | --- | --- |
| 在制品仓（WIP） | 已发到车间、仍在生产过程中的物料 | 原料已领到车间，加工还没有完成制造入库 |
| 半成品仓 | 已经完成一个独立生产阶段、按半成品编码入库，可留存供后续领用 | 先做好 100 个壳体入库，装配领走 60 个，库存还剩 40 个 |
| 成品仓 | 已经完成最终制造入库、可供销售交付的产品 | 壳体装配成为完整产品，再入成品仓 |

**本地候选版本已实现可选的默认半成品仓，并通过本轮自动化验证，尚未发布 prod。**未安装该版本时，新建仓库或只修改物料默认仓仍不能自动改变快捷排产路线。

管理员按以下顺序配置：

1. 准备半成品物料编码、库存单位、维护库存属性及适用的批次规则。自制半成品有自身已提交且启用的 BOM；上层 BOM 明确填写该半成品的数量和子 BOM。
2. 建立本公司启用的非分组末级仓库，例如“半成品仓 - 智”。它不能与在制品仓、待检隔离仓、报废仓或待返工仓共用。物料组可以继续设“半成品”，方便分类查询；物料组名称不会决定收发仓库。
3. 打开 Company（公司）→ 本公司 → 库存与生产 → 生产区域 → 默认半成品仓，选定后保存。若未看到该字段，先核对候选版本与公司修改权限。清空此字段表示沿用该订单的原料来源仓，不额外建立一条半成品收发路线。
4. 在“权限管理／岗位与范围”给负责该仓的库房人员、生产主管和其他需要查看或操作的岗位补充仓库范围；公司范围与原有岗位权限仍须保留。设置默认仓不会自动扩大用户权限。
5. 重新打开公司设置确认保存，并在“开用前检查”查看半成品仓是否可用。指定仓无效时应先处理，不会悄悄改回其他仓继续排产。

| 选择 | 新建快捷生产计划的行为 |
| --- | --- |
| 默认半成品仓留空 | 原料与自制半成品继续共用原料来源仓；可用物料组和独立编码分类盘点 |
| 指定有效半成品仓 | 按上层 BOM 子 BOM 参与自制的半成品，在这里抵扣现货、预留、完工入库和供上层工单领用；同一工单里的其他原料仍从原料来源仓领用 |
| 外购半成品，或上层 BOM 对该行不展开子 BOM | 仍按普通采购用料走原料来源仓；不能因为物料组叫“半成品”或物料另有默认 BOM，就自动转到默认半成品仓 |

这项配置只决定新建任务的路线。**已经生成的工单保留自身用料来源和完工目标仓，后续改公司默认仓不会自动迁移旧单、库存或预留。**既有工单的正常退料回原发料来源，补产继续送往它原本需要的仓库。若要中途更换仓库，先由实施人员核对未完工任务、库存和预留，不能仅修改公司字段后直接搬货。

分仓时，同一个工单内的相同物料编码应统一供料方式；不要一部分填子 BOM 自制，另一部分又按外购原料领用。若需要同时分开管理，请使用不同物料编码。一个消费分支为同物料指定多个不同 BOM 时，也应先明确补产方案。

小单验收至少包括以下两种数量情形；均假设无损耗、其他原料足够，并逐步核对单号、仓库、数量、预留及下一责任人：

- 半成品仓有 100 个、上层需要 60 个：排产识别并预留 60 个，不再安排这 60 个半成品生产。库房发料后半成品仓剩 40 个、WIP 增加 60 个；上层制造入库耗用对应 WIP 数量并增加成品。
- 半成品仓有 40 个、上层需要 60 个：先使用现货 40 个，只补产 20 个；半成品子工单的原料需求也只按这 20 个展开。补产完工入半成品仓后供原上层工单领用，不把原料仓里同编码的数量误算作半成品仓可用库存。

还要保留一例“默认半成品仓留空”的共仓回归，并检查修改公司设置前已生成工单仍使用原仓库。不要把公司默认 WIP 仓或全局默认原料仓直接改成半成品仓来代替这一可选字段。

增加半成品仓不要求开启 Track Semi-finished Goods。该原生功能涉及特殊 Job Card，当前简化工人报工入口不支持这一模式。普通半成品各自建 BOM、分别生产入库，继续按普通工单处理。

核对范围：2026-09-22 本轮通过 158 项后端单元回归、11 项隔离数据库真实库存集成场景和 7 项前端检查。集成覆盖库存抵扣与预留、分仓制造、改配置后的旧单、退料重领、旧数据兼容及直接从 WIP 耗料的补产。本轮不是 prod 发布或工厂岗位现场签收，现场仍应按本节例子验收。原生能力参考：[多层 BOM](https://docs.frappe.io/erpnext/managing-multi-level-bom)、[工单来源仓与目标仓](https://docs.frappe.io/erpnext/work-order)。

## 4. 物料、单位、客户与供应商

| 资料 | 最少要核对的内容 | 常见错误 |
| --- | --- | --- |
| UOM／单位 | 件、kg、米、箱等；整件单位是否必须为整数 | 把采购 1 包当成库存 1 kg |
| Item Group／物料组 | 原材料、半成品、成品等现场能理解的分类 | 分类太碎，维护人员分不清 |
| 原材料 Item | 编码、名称、规格、库存单位、维护库存、采购属性、所属公司默认仓 | 同一实物重复建码；不同规格共用一个编码 |
| 自制半成品 Item | 同样需要物料编码、库存单位和仓库；需要独立生产时准备自身 BOM | 只在备注里写半成品，无法管理库存与生产 |
| 成品 Item | 编码、规格、库存单位、维护库存、销售属性、公司成品仓；需生产时有默认 BOM | 成品默认仓误设原料仓，库存判断与发货去向不一致 |
| 单位换算 | 例如 1 包＝25 kg、1 箱＝20 件；按实际建立物料的换算关系 | 采购单位、BOM 单位、库存单位含义不一致 |
| Customer／Supplier | 正确名称、分组及页面必填信息；业务联系信息和交货条件 | 演练结束后正式单据仍选测试客户／供应商 |
| 销售／采购价格 | 需要建议价时维护对应价格表及 Item Price；由业务确认币种、单位、税价口径 | 快速开单仍需核对成交单价，不能把建议价当最终确认 |

是否启用批次要在第一次库存交易前决定。需要时：Stock Settings 启用物料批次功能 → 对目标 Item 勾 Has Batch No → 配自动建批与编号规则 → 核对出库自动选批规则 → 库房试跑。自动预留批次另按业务决定；无批次需求的物料照常使用。

当前快速开单已支持批次产品，实际批次由库房在原生库存单确认。序列号产品、规格变体、委外和其他高级订单条件仍应走标准单据并单独验证。已有库存流水的老物料不要直接切换批次属性；先确定现存库存、批号和切换方案。详见 [09｜批次自动管理与追溯](https://rcnz1aofm14f.feishu.cn/wiki/JAzTwkSITixJK2kGv1JcIZPundh)。

## 5. 工作站、工序、BOM：决定怎样做、用多少料

1. 建立 Workstation（工作站），按实际机器、工位或生产线命名。启用工作站，填写产能，并在 Working Hours（工作时间）维护实际班次，例如 08:00–12:00、13:00–17:00；核对工作日、节假日以及计划开工时间落在可用时段内。只填写工作站名称不等于已配置可排产日历，不要照抄演练站的全天时段。
2. 建立 Operation（工序），例如切割、打磨、装配，关联正确工作站；在 BOM 工序中核对顺序及标准耗时，保持与现场一致。首次可选一道普通装配工序验证。
3. 先做自制半成品的底层 BOM，再做成品的上层 BOM。每张 BOM 核对产出物料、产出数量／单位、每项原料／半成品的用量、工序和工作站。
4. 由生产主管确认后：保存 → 提交，并确认 Is Active（启用）及 Is Default（默认）。只有草稿、只有启用但未提交、或不是默认，都不能作为快捷生产路径的有效默认 BOM。
5. 准备用工人手机报工的产品，BOM 要包含实际工序；创建工单后应能生成对应 Job Card，再由主管派工并指定审核责任人。

首次小单建议先配置：FIRST-FG 产出基数 **1 件**，投入 FIRST-RAW **2 件**，含一道普通工序和对应工作站；销售并生产 **3 件**成品时，总需求应为 **6 件**原料。BOM 的产出基数仍为 1，不要因为要下 3 件订单就把投入量直接改成 6 而保持产出 1。

原有数量例子：BOM 产出 1 件成品，使用 0.2 kg 原料；生产 100 件，理论需求为 20 kg。若 BOM 产出基数写成 100 件，就应配 20 kg，而不是仍填 0.2 kg。损耗按本厂规则单独说明，先把一个样品的数量算对，再批量建 BOM。

Manufacturing Settings → Enforce Time Logs（强制工时日志）保持关闭（OFF），保存后重新打开确认：当前简化工人报工入口会拒绝该开关开启的配置。不要把它误当成“开启计时工资”的开关。是否启用产能规划由本厂排程方式决定；启用时先补齐工作站日历，关闭时由主管承担排程确认。

第一轮用普通 Job Card 验证。纠正任务单、带子工序的 Job Card、委外 Job Card，以及开启 Track Semi-finished Goods 的特殊 Job Card，不属于当前简化报工支持范围。这与“普通半成品物料分别建 BOM、分别生产”不是同一个概念，复杂工艺需先单独试跑。

## 6. 员工、工价、通知和手机使用

销售、采购经办、库房、生产主管、工人、工资核算、负责人分别明确到人。可以一人兼岗，但要明确哪一步由谁做；账号仍使用本人账号。权限管理里同时核对岗位能力和公司／仓库／员工数据范围。库房还要验证原生收货、库存、发货单的提交与打印权限。

### 6.1 给岗位配权限，还要配公司和仓库范围

管理员在“权限管理／岗位与范围”选择已保存的 User，配置岗位及数据范围，点击“保存岗位与范围”后重新进入确认。默认公司只是新单据的默认值，不能代替公司范围授权；能打开工作台，也不能代替原生单据的创建和提交权限。

| 岗位 | 本次小单责任 | 必须核对的范围 |
| --- | --- | --- |
| 销售 | 提交销售单、核对交付 | 本公司客户和销售订单 |
| 采购责任人（示例由老板岗位承担） | 提交缺料采购申请及采购订单 | 本公司、供应商和相关采购单据；本轮生产主管默认只读采购信息 |
| 库房 | 收货、发料、制造入库、发货的最终提交 | 本公司原料仓、在制品仓、成品仓，以及对应原生单据权限 |
| 生产主管 | 创建计划工单、申请发料、派工、报工审核、申请入库 | 本公司生产和审核范围；派工里的审核人填写 User，不是 Employee 编号 |
| 工人 | 本人任务开工、暂停／继续、报工 | 唯一在职 Employee 绑定和本人任务；不兼任主管、工资核算、老板或系统管理员 |
| 工资核算 | 生成月度工资草稿 | 明确的本公司范围权限和目标员工范围；只有工资角色或默认公司仍不够 |

派工与审核责任分工要在试单前明确；工人不能审核自己的报工。普通生产主管默认负责自己的审核任务，派给工人的数量合计应等于该任务数量。不要为解决按钮缺失给普通岗位全部管理权限；先核对该动作是否属于此岗位，再核对角色与数据范围。

### 6.2 首次计件规则与通知

Operation Wage Rate（计价规则）：填写公司、工序、启用计件／计时、每件单价／每小时单价、生效日期及必要的失效日期；开工前确认已有当日适用规则。BOM 的工序成本与员工工资规则用途不同，填写 BOM 成本不会自动生成员工计件工资。作业开始时形成工资快照，改工价后要核对新旧作业归属。

三件小单的规则：选择本公司和该道工序，仅启用计件，单价填 **2 元／件**，生效日期不晚于实际开工日，并确认没有冲突的有效规则。工人完成 **3 件**时，报工工资快照应为 **6 元**；报工仍待审核时，不能把它当成已审核工资，更不代表已付款。

工资核算从“月度工资汇总”列表进入，窄屏时展开右上菜单 →“生成月度汇总”→ 选择公司、工资月份和工人 →“生成或刷新草稿”。普通工资核算岗位没有“报工审核”入口；审核由生产主管完成，工资岗位汇总已审核结果。生成后打开草稿核对员工、月份、来源报工和 6 元金额，草稿不等于工资已确认或已付款。

| 恒算 ERP 系统设置 | 建议 | 怎样核对 |
| --- | --- | --- |
| 计时工资允许手工填写工时 | 需要工人填写计薪分钟时开启；按计时器实际分钟计薪时关闭 | 两种方式都保留实际计时段；用一条作业核对报工及工资结果 |
| 启用流程通知 | 开启 | 派工、审核、收货等真实交接时，下一责任人的系统通知能收到并打开正确单据 |
| 启用声音提示 | 按现场需要开启 | 个人静音、浏览器和手机音量仍会影响声音；以通知列表和业务状态为准 |
| 追加接收用户／岗位 | 只补充实际需要知情的人 | 不会替换默认责任链，也不能绕过公司和岗位权限 |
| 启用手机应用安装 | 需要桌面图标时开启；HTTPS 访问网址填正式域名 | 用工人真实手机测试登录、滑动、开工／暂停／报工；添加桌面图标不等于已验证离线使用或系统级推送 |
| 打印和扫码 | 核对公司抬头、地址、电话、Logo 和默认工厂打印格式 | 用实际打印机试打一张；纸张、中文、数量和二维码可读；手机扫码使用实际设备验收 |

## 7. 期初库存与正式业务切换

1. 约定一个期初截止日期，由库房按“物料＋仓库＋库存单位”盘点；有批次的还要逐批数量及必要有效期。
2. 准备期初数量和估值单价，由库房及财务确认。通过原生 Stock Reconciliation（库存调账）等合适的期初库存入口录入并提交；批次物料使用实际版本支持的批次明细。
3. 用 Stock Balance（库存余额）及必要的批次明细复核：仓库、数量、价值和实物一致。建 Item 或写备注不会增加库存。
4. 另列上线前未结销售单、采购在途、在制工单；确定从哪一步接续，避免同一数量既录期初又补做收货／入库。
5. 基础资料及期初确认后做一份完整备份，记录对应版本与备份时间。演练尽量在隔离站点；若在 prod 执行，应先由业务负责人明确允许的订单和过账范围。

备份应覆盖数据库、公开／私有附件和站点配置；存在加密密钥时一并保管，并保留匹配的代码／镜像版本。整站恢复会回退备份时间之后的全部变化，不能当成“只删除测试单”的按钮。正式业务开始后按正常更正／取消流程处理差错。

## 8. 用一张能算清楚的小订单验收

### 8.1 首次三件小单：从下单到工资草稿

先在隔离站完成。管理员准备好前面各项资料，之后各岗位退出并用本人普通密码登录接力。样例为 FIRST-FG 3 件，每件耗 FIRST-RAW 2 件，原料期初 0、采购 6 件；一名工人做一道工序，计件 2 元，目标工资 6 元。无批次、无损耗、无半成品子 BOM，销售和采购价格由业务另行确认。

**以下是操作要求和预期数量，不是已通过记录。**本轮实际进展、已经完成和仍待验证的步骤统一见文末验收报告；业务表格不预填通过。

| 顺序与负责人 | 页面操作 | 提交后应核对什么／交给谁 |
| --- | --- | --- |
| 1．销售 | “快速开单”选客户、FIRST-FG 3 件、单价和交期，核对提交 | 销售单已提交，成品现货 0、需生产 3，原料需求 6；交生产主管。下单不会自动代做全部采购和生产 |
| 2．生产主管 | “生产计划中心”选择该订单，创建生产计划与工单 | 工单产量 3、原料 6，来源仓／在制品仓／成品仓正确，生成一道任务量 3 的工序任务；缺料交采购责任人 |
| 3．采购责任人 | “缺料采购”选本公司和订单，生成并提交原料 6 件采购申请 | 同一缺口只申请一次；采购申请不等于已到货 |
| 4．采购责任人 | “采购跟进”分配供应商和 6 件数量，填单价，生成采购草稿，再打开核对提交 | 采购订单已提交、待到货 6；交库房。这是采购在途，不需要把数量提前放进在途物料仓 |

| 6．生产主管 → 库房 | 主管对该工单“申请发料”；库房从“核对生产发料”打开原单并提交 | 原料仓 6→0，在制品仓 0→6；申请或草稿不算已发料。交主管派工 |
| 7．生产主管 | 对该道工序派工，选择工人 Employee，数量 3，核对审核 User | 工人收到本人一条任务，任务量 3、工价 2 元；发料和工价未满足时先处理原因 |
| 8．工人 | “待开始”开工，“正在做”中暂停／继续，实际做完后报工 3 件 | 计件快照 2 元、金额 6 元，报工 Pending（待审核）；原料仓 0、在制品仓 6、成品仓 0。交主管 |
| 9．生产主管 | “报工审核”核对数量、时间和 6 元，审核通过 | 报工已通过，工序任务完成 3；成品库存仍为 0，继续申请入库 |
| 10．生产主管 → 库房 | 主管“申请入库”；库房“核对完工入库”，打开制造入库原单提交 | 实际耗用在制品仓原料 6，在制品仓 6→0，成品仓 FIRST-FG 0→3 |
| 11．库房／有权限订单岗位 | 在订单工作台预留已完成成品，或处理原订单的“待回补订单” | 3 件成品明确分配并预留给原销售订单，实物仍为 3；不能重复占用。继续安排发货 |
| 12．库房 → 销售 | 为本订单创建发货草稿，打开 Delivery Note 核对成品仓 3 件后提交 | 成品仓 3→0，销售已交 3／3、未交 0，剩余有效占用结清；销售回查交付。尚未开票不影响这次交付数量验收 |
| 13．工资核算 | 打开“月度工资汇总”；窄屏展开右上菜单，点“生成月度汇总”，选择公司、当前自然月及该员工，再点“生成或刷新草稿” | 只纳入已审核报工，本单 3×2＝6 元且只计一次。当前月未结束，保留草稿；不强行确认，也不算已付款 |
| 14．各岗位 | 重登回查订单、工单、本人报工、库存和工资草稿 | 没有遗留活动计时、待审核报工、重复订单或未提交库存草稿；通知能打开正确业务 |

数字只看这一条主线：原料仓 FIRST-RAW **0→6→0**；在制品仓 FIRST-RAW **0→6→0**；成品仓 FIRST-FG **0→3→0**；已审核报工 **3 件**，本单工资草稿 **6 元**。审核报工不会自动增加成品库存，库存预留也不等于出入库。

每一步记录单号、操作者、前后数量、下一责任人及通知是否打开。采购、库房和工资岗位如果缺按钮，先核对分工与授权；不能由管理员后台代做后记为该岗位通过。若工厂另有期初或其他订单，按本单来源记录核对工资与库存，不把全公司合计强行要求为 6 元或 0 库存。

### 8.2 原有百件教学例：继续用于数量换算和分批发货

教学示例：单工序产品 100 件，单件耗原料 0.2 kg，无损耗；原料期初 0，采购到货 20 kg。以下数字仅用于教学，不代表已经在 prod 执行。第一轮也可选数量更小的真实订单。

| 岗位与动作 | 完成后检查 | 下一责任人 |
| --- | --- | --- |
| 销售：开 100 件订单 | 订单已提交、产品／交期／单价正确；下单尚未收发库存 | 生产主管 |
| 主管：确认需求和工单，提出缺料采购 | 生产量 100 件、需求 20 kg；同一缺口未重复申请 | 采购经办 |
| 采购：下单；库房：到货核对并提交 | 原料仓实际入库 20 kg，采购剩余及到货通知正确 | 生产主管／库房 |
| 主管申请发料；库房提交生产发料 | 原料仓减少 20 kg、WIP 增加 20 kg；只有申请草稿不算已发料 | 主管派工／工人 |
| 工人开工、报工；主管审核 | 100 件报工数量及工资口径正确；此时成品库存不因审核自动增加 | 主管／库房 |
| 主管申请完工入库；库房核对并提交制造入库 | 实际耗用 20 kg，WIP 对应材料结清，成品仓增加 100 件 | 销售／库房 |
| 销售安排发货；库房提交 60 件、再 40 件 | 两次发货对应同一订单，成品余额 40→0；订单交付和预留释放正确 | 协调人验收 |

每一步记录单号、前后数量、下一责任人和通知是否收到。先完成正常链，第二轮再验证分批采购、多人派工、退料、待检、报废和返工。批次启用时，另逐批核对实际耗用、成品产出和客户去向。

## 9. 让工厂准备这些资料就够了

以下是业务资料收集清单，不是 ERPNext 直接导入模板。工厂填自己知道的业务内容，实施人员映射系统字段。先手工建 1 个正确样例，从当前 prod 导出对应模板，试导入 2–3 条并核对后再批量导入；BOM 子表保持父子行结构与顺序。

| 资料表 | 让工厂填写的列 |
| --- | --- |
| 员工与岗位 | 姓名、工号、手机号、所属公司／部门、岗位、主管、需要哪些仓库的权限、是否计件／计时 |
| 仓库 | 仓库名称、用途、所属公司、现场位置、负责人 |
| 物料 | 编码、名称、规格、原料／半成品／成品、库存单位、采购／销售单位和换算、默认仓、是否批次 |
| 工序与工作站 | 工序名称、先后顺序、工作站／机器、标准耗时、需要的生产日历 |
| BOM 用料 | 成品／半成品编码、产出基数、每种投入物料编码、用量和单位、对应工序、正常损耗说明 |
| 工资规则 | 公司、工序、计件单价／计时单价、生效日期、负责人 |
| 客户与供应商 | 名称、类型／分组、联系人、交付地址、常用物料及业务确认的价格／付款条件 |
| 期初与未结业务 | 盘点日期、物料、仓库、数量、库存单位、估值单价、批号／有效期；未结订单和在制品另列 |

导入顺序：单位／物料组／仓库 → 客户供应商、物料、工作站 → 工序 → 底层半成品 BOM → 上层成品 BOM → 员工账号关联及工价 → 期初库存。用户密码由管理员管理，不放在通用资料收集表里。BOM 先保持草稿，主管确认后再提交。

## 10. 正式开工前逐项打勾

- [ ] 公司、业务日期、默认仓库和账户已确认；没有拿汇总仓或测试公司做正式收发。
- [ ] 员工分别用本人账号登录；工人只看到本人任务，库房能提交授权原单。
- [ ] 待生产产品都有已提交、启用、默认的 BOM；工序、工作站和原料用量已经主管签认。
- [ ] 库存预留 ON、自动预留初期 OFF、负库存 OFF；Enforce Time Logs OFF，工作站工作时间和有效工价已核对。
- [ ] 期初库存与实盘一致；历史未结订单和在制品已有接续方案。
- [ ] 一张小订单完成岗位接力，订单、报工、库存、工资草稿和预留数量对得上；待审核报工不算完成。
- [ ] 真实岗位收到该收到的通知；手机和实际打印机完成必要操作验证。
- [ ] 自动备份、异地保存、失败告警和隔离恢复已验证；正式切换日期和负责人已确定。

已安装本次候选修复的站点，可由管理员从“生产计划中心 → 开用前检查”进入设置页，选择公司后点击“重新检查”。按提示补齐配置再检查；页面提示需管理员处理的项目，由有权修改该原生设置的管理员完成。该入口是否已出现在 prod，仍以实际发布版本为准。

新增“开用前检查”核对的是全局基础配置：当前公司、三个生产默认仓及可选的默认半成品仓、库存预留、负库存和强制工时日志；手机号／用户名登录及自动预留作为按需设置显示。公司的在制品仓、成品仓必须明确指向本公司启用的末级仓，缺失或无效都显示“需要处理”。原料默认仓指向不存在的仓，或指向本公司已禁用／分组的仓时，也显示“需要处理”。默认半成品仓留空属于正常共仓模式；明确选择了无效仓库时显示“需要处理”，不自动换仓。

来源仓有一个需人工核对的特殊情况：库存设置的默认仓是全局值；当它未设置或属于别家公司，而现有解析能找到本公司启用的末级来源仓时，页面会显示实际采用的仓及“需要核对”，要求在工单确认。多公司场景不要为每家公司反复切换全局默认仓。此提示不适用于公司的在制品／成品默认仓，也不能掩盖已经明确配置的无效来源仓。

原有业务路径在部分情况下能按仓库名称或订单行寻找替代值，这不等于新增开用检查已经通过。**全局开用检查不会逐个产品检查 BOM。**原有按产品检查只有带入待检查产品时才核对其已提交、启用的默认 BOM；实际创建生产工单仍会核对该订单产品的 BOM 和仓库。因此全局配置检查通过后，仍要按第 5 节逐项维护产品、BOM、工序和工作站，生成小单后核对真实用料及三个仓库。员工、工价、库存、通知和恢复也须另行验收。

整理依据：当前项目初始化检查、仓库默认值、工人报工限制、总设置字段，以及 2026-09-17 生产发布记录。原生登录行为另参见 [ERPNext 官方：Adding Users](https://docs.frappe.io/erpnext/adding-users)。配置、真实岗位试跑及设备验收结果应由本厂另行记录日期和责任人。
