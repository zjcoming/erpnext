# 工序集中派工首版：实施与验证记录

分支：`codex/operation-dispatch-pool`。基线：`cf72f3dd70`。

本次只增加集中操作入口，目标是减少找单、重复选人及逐单打开弹窗。当前代码不改变生产计划、工单、工序提交、个人报工、工资和库存的业务模型；不迁移历史数据、不新增业务 DocType。

## 实际交付

- 生产计划中心保留“按订单查看”，受发布开关和生产审核权限控制新增“按工序派工”。
- 仅展示已提交计划下、有效已提交工单中的普通草稿工序任务；按公司、工序名称、来源/产品关键词、派工情况筛选。每页最多 20 张，显示来源、产品描述、工作站、交期、数量及单位、原规则的阻塞原因。
- 当前页同公司任务多选，一次选择本轮共用工人；逐卡预览中可调整多人数量。合计仍须等于各卡任务量，正式提交复用原完整校验。
- 每卡独立请求并顺序执行；结果逐卡显示。停止或离开页面仅停止尚未提交的卡。超时先查询服务器事实，无法确认时停止后续请求，已有记录不冒称本次成功。
- 新写入口在原锁顺序内检查保留的派工、报工、原生计时、数量移动及完成/损耗事实，拒绝覆盖。旧单卡接口不传新增的内部参数，其原替换规则保持。
- 页面刷新及预览不调用派工、不创建库存预留。正式派工仍可按旧规则产生直耗料预留、派工通知等原有副作用。

固定班组/默认人员的长期配置、后台自动派工、跨工单合并报工、首次部分发料放行、部分工序流转和批量库存动作未纳入。已有部分发料、领退料及出入库仍走原入口。

## 启用与回退

发布开关为站点配置 `enable_operation_dispatch_pool`，缺省关闭；仅接受 `true`、`1` 或字符串 `"1"`。启用之前先按项目原部署流程发布代码与静态资源、清理缓存并重启应用进程。无本功能专用数据迁移。

在目标 bench 中将示例站点名替换为实际试点站点：

```sh
bench --site <site-name> set-config enable_operation_dispatch_pool 1 --parse
bench --site <site-name> clear-cache
```

用户重新加载页面或重新登录后才获得新的 boot 状态。开关打开不授予新角色或公司权限；库存、工人等原权限仍需预先配置。当前只有一个功能开关，没有单独的“只读开放”开关，首轮可在隔离站点先只观察列表，实际试点应控制账户和任务范围。

关闭方式：

```sh
bench --site <site-name> set-config enable_operation_dispatch_pool 0 --parse
bench --site <site-name> clear-cache
```

关闭后新的读写请求会被服务器拒绝，刷新页面隐藏新视图；已进入事务的请求可能继续完成，需要核对结果。已生成的原类型派工记录继续通过旧流程使用，不自动删除派工或回滚库存、报工。

## 剩余边界

- 未做生产规模数据量压测；查询有分页、页内按工单复用上下文，但跨大工单集合的耗时仍需实际数据验收。
- 样式已包含窄屏布局，尚未进行真实手机端岗位验收。本次浏览器验证为桌面环境。
- 不持久化整批请求日志；刷新或关闭浏览器后从原派工记录核实。保留的业务历史受到首次检查保护，但旧入口合法删除尚未开工的安排后允许再派。
- 页面集中查看不会新增实物子批次与工人之间的关联；追溯精度保持原系统边界。
- 开关关闭与成功记录的可用性由自动化验证和浏览器切换验证覆盖；正式启用前仍需主管用真实业务样本确认误选防护与操作习惯。

## develop.localhost 从快速开单到发货的浏览器补验

2026-09-28，在独立 v16 本地试用站使用老板与工人身份，真实通过 Chrome 创建销售订单 `SAL-ORD-2026-00002`（10 件三工序金属支架），经生产计划 `MFG-PP-2026-00004`、工单 `MFG-WO-2026-00004`、采购收货、工单发料，依次完成切割/钻孔/打磨的工序池派工、工人计时与报工、老板审核，再提交成品入库、回补来源订单、提交发货单 `MAT-DN-2026-00001`。

实际发现并修正：

- 试用站公司缺默认在制仓与成品仓，原示例工单直接指定仓库掩盖该初始化遗漏。通过正常 Company 保存补齐配置，并修正本地种子脚本；无需修改原 ERPNext 仓库校验。
- 老板后端已有生产管理能力，前端 `canManageWorkerAssignments` 漏含老板角色，导致发料/原派工入口缺失。前端角色判断补齐，并验证普通销售、工人仍不显示相关入口。
- 工人 Link 字段的迟到 onchange 会清空刚生成的派工预览。仅在预览人员实际改变时使预览失效；确认动作再次校验当前选择，换人必须重新预览。浏览器使用下拉选人复验，一次点击正确进入确认阶段；回归用例覆盖迟到校验、未完成 onchange 时换人及显式换人。

本轮相关 JS 98 项通过。只读数据库核对确认：订单交付 100%，工单和三张工序任务全部完成；三条报工各 10 件、合计工资 100 元，与 Job Card 计时记录一一关联；发料、完工入库、发货均已提交；剩余 Stores 原料 20、成品库存 0。用户原 20 件订单未安排工单，原三张种子任务仍未派工。

本次未开票或收付款；非批次示例不能替代批次追溯验收。另记录原有引导问题：同产品多订单时，完工成品回补前共享库存优先分配可能令来源订单先显示“待创建生产计划”，需要展开点“回补订单”；本次未改变库存分配或生产数量算法。详细操作记录、断言脚本/结果与截图见本地 `development/operation-dispatch-20260928/`。
