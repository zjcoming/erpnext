# 岗位权限复查（2026-09-28）

本轮检查了七种业务岗位模板、页面入口、原生单据权限、关联字段选择以及公司/仓库/员工范围。生产账号检查使用只读事务；业务操作测试全部在隔离的 v16 站点完成。

## 确认的问题

1. **老板及生产主管无法打印生产任务单。** Job Card 已有 read/select，但没有 print。已有原生制造管理角色的历史账号可以打印，掩盖了新岗位账号的问题。新增真实工单生成任务单的回归测试，在修复前两个岗位均报 PermissionError。
2. **工资核算人员不能在计价规则中选择公司和工序，老板也不能选择工序。** 原生 Link 查询需要对应的 select 权限，只有计价规则本身的 create/write 不够。修复前使用原生 search_link 复现 Company/Operation 的 PermissionError。
3. **一名启用的工人账号没有在职员工绑定。** 生产共检查八个启用的业务账号，其中一人没有对应员工档案，无法进行本人任务和报工。账号用途、员工信息需由用户确认后补齐；本次未猜测或创建员工资料。具体账号信息仅保留在本地审计证据中。

生产权限与当时已部署代码的单据矩阵、页面角色及岗位模板均一致，没有发现这三类配置漂移。前两项属于代码模板遗漏。

## 修复范围

- 生产主管的 Job Card 增加 print，老板通过模板继承该权限。Job Card 仍不能直接创建或修改，跨公司打印仍被拒绝，工人仍使用个人任务 API。
- 工资核算模板为 Company、Operation 增加 select；老板继承 Operation 的 select。未开放公司/工序资料的创建或编辑，也未为工资岗位增加其完整读取权限。
- 修正销售岗位描述中“仍需原生销售权限”的旧文字，使其与自动配置的单据权限一致。
- 原生采购审批、库存过账、系统设置和员工自助的既有职责不变。
