# 系统内单据扫码

更新日期：2026-09-11。二维码已改为不含访问地址的系统内单据码。范围为统一入口、采购订单 / Job Card / Purchase Receipt / Stock Entry / Delivery Note 二维码、权限校验及定位，业务操作由用户在原页面确认。

最新默认模板、库存扩展和发布说明见 [工厂默认打印与库存扫码](factory_print_suite.md)。当前资源 JS v13 / CSS v7；下方历史回归记录保留当时版本。

## 使用

1. 登录后点击当前业务页右上角绿色“扫一扫”按钮，或进入 `/desk/document-scan`；业务页和主页面菜单也保留同一入口。手机上的“我的任务 / 待开始”“正在做”“我的记录”无需展开菜单即可进入。
2. 手机、平板或电脑点击“开始扫码”，允许摄像头权限后可见实时画面，将二维码放入四角框中；有多个摄像头时可切换，点击“关闭相机”结束。手机远程访问需 HTTPS；`localhost` 仅供本机开发使用。
3. 二维码扫码枪使用键盘输入模式：先点击扫码页输入框，再扫码并回车。粘贴完整系统内码也按确定的扫码目标处理。
4. 手动输入单号片段、物料名或供应商关键词，点击“搜索单据”先列出候选项，只有一条也不自动跳转。可以筛选五类单据；库存类型支持编号、供应商 / 客户、作业类型 / 工单检索。结果最多显示 20 条，更多时提示缩小搜索范围；完整编号优先展示。搜索时收起相机区域、不播放扫码成功音。
5. 点击候选项后重新校验权限：采购单按读取权限打开原单；管理账号打开生产任务单按 Job Card 读取权限，不要求派给管理员本人；工人打开生产任务仍按本人 Active 派单定位。
6. 工人任务进行中 / 暂停进入“正在做”，其他当前任务进入“待开始”；展开所在分组和任务详情，滚动定位并短暂高亮。点击时派单已撤销则保留列表并提示联系主管。收货、计时、报工等业务操作仍由用户在原页面确认。

扫码成功找到有权限的单据后播放两声上扬提示音；已解码但码无效、无权限 / 未派单、找不到单据或读取失败时播放三声下降错误音，并保留具体原因。两种提示音均提高信号幅度并延长，便于车间辨认。识别后结束本次取景，避免同一码持续入镜反复响，重新点击“开始扫码”可再次扫描。页面“提示音开 / 关”同时控制两种音效，关闭会立即停止正在播放的声音；账号已设置静音时保持静音。手动关键词搜索、点击搜索结果、离页或切换账号后的过期响应不触发扫码音效。

手机可先点击“成功试音 / 错误试音”检查两种节奏和媒体音量。iOS 音频在用户点击时初始化，支持 Audio Session 的浏览器暂时使用 playback 类型；相机关闭后若 AudioContext 被中断，播放前最多等待 500 ms 恢复。音效结束后关闭音频并恢复先前的会话类型；播放受阻不影响查单或跳转。网页无法提高手机系统媒体音量，车间实机响度仍需用户验证，自动测试不能代替手机听感验收。

扫码不会创建收货单、开始计时、报工、改变派工或扩大权限。普通工人仍受现有角色隔离与员工身份规则约束。管理账号扫描 Job Card 第一版也不跳过本人派工规则。

普通手机相机扫描新码只得到文本，没有可直接访问的系统网址。用户先登录系统，再使用系统内“扫一扫”。此调整不改变系统本身的网络可访问范围；如需限制为内网访问，应由现有网络部署决定。

## 协议与边界

```text
HSERP|1|<32 位小写十六进制系统标识>|purchase-order|<base64url(UTF-8 单据编号)，去掉 = 填充>
HSERP|1|<32 位小写十六进制系统标识>|job-card|<base64url(UTF-8 单据编号)，去掉 = 填充>
```

码内只有版本、系统标识、单据类型和编号，不包含域名、IP、端口、价格、数量或登录凭据。系统标识是公开的命名空间，编号是可逆编码，两者均不提供授权或保密能力。

系统标识在安装 / 迁移时一次生成，保存在 `DefaultValue` 的 `parent="__default"`、键 `process_document_scan_site_id` 中。读取时明确使用全局值，不合并用户级默认设置；已登录用户通过 boot 获取同一个标识。扫码或打印不会临时生成标识，未初始化时会提示管理员完成升级，并禁用扫码提交和摄像头。

更换域名、IP 或端口不会让新码失效。备份和正常恢复必须保留该标识；从完整数据库克隆出独立工厂时，需要为新工厂重新初始化系统标识并重印其单据，以免两个独立系统共用命名空间。不同工厂在同一个站点中仍按原有公司与单据权限隔离。

新增类型键为 `purchase-receipt`、`stock-entry`、`delivery-note`，编码方式与上述示例相同。

前后端均验证完整单据码，只允许上述五种类型、规范编码及长度，拒绝不同系统标识、未知版本、非法输入和旧网址码。只读 GET 接口 `process_simplification.api.document_scan.resolve` 接收完整 `code`，服务端独立校验系统标识，再检查当前会话的读取权限或本人派工。生产定位状态仅在当前页面会话中保存，按用户隔离、一次消费、60 秒过期。

旧版 `/desk/document-scan/<类型>/<编号编码>` 地址只显示停用和重印提示，不自动查单。旧网址码也不能粘贴到输入框继续使用。此前保存的 PDF 和纸质单据需要重新打印。

生产页先刷新当前任务，再进行匹配。若查找期间任务由待开始转为进行中，只允许一次列表修正跳转；再次变化时给出刷新提示。定位在公共加载器恢复折叠与滚动状态后执行，避免被后台刷新覆盖。

### 2026-09-11 取景画面与提示音修复

画面不显示的直接原因：旧 CSS 使用 `.ps-scan-reader:empty { display: none; }`，空容器的 `clientWidth` 为 0；当前 html5-qrcode 的 `RenderedCameraImpl` 在插入视频前读取这个宽度，并将它设为视频宽度，产生不可见的视频。开发站点已实际读取到旧空容器的宽、高为 0。
