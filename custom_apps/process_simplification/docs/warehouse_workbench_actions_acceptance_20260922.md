# 恒算 ERP：库房工作台采购待办实施与验收

日期：2026-09-22。代码基线：`rc/develop-v16`，`ef38a306ca228a1993d45f46d449121f1d67d0c4`。

## 问题与结果

快捷开单会提醒库管查看缺口，但原库房工作台只收集库存草稿、发货草稿和待收采购单。订单尚未生成这些单据时，库管会收到通知却看不到下一步。

本次在原有六类单据上方增加采购待办：

| 提示 | 显示内容 | 处理入口 |
| --- | --- | --- |
| 缺料待处理 | 当前缺料物料项数、关联销售订单数 | 对应公司的缺料采购页 |
| 采购申请待跟进 | 尚需下单或确认的采购申请张数 | 对应公司、范围为“待下单 / 确认”的采购跟进页 |

有待办时显示数量和处理按钮；没有待办时收起卡片，显示简短空态。错误或计算中显示待核对状态，不显示为零。

## 业务口径

- 缺料复用现有缺料采购计算和短期展示缓存，扣除库存、采购申请和采购订单覆盖；物料按公司、物料、来源仓口径计项，订单去重计数。
- 生成并提交采购申请后，已覆盖的缺料退出缺料提示，申请进入采购跟进。
- 采购草稿尚未更新原生已订购量，因此申请仍需跟进。
- 部分下单时，剩余部分保留采购跟进；已正式下单部分出现在原有“采购待收货”。
- 全部下单后，申请退出“待下单 / 确认”范围；后续按原有采购收货流程处理。
- 取消采购单或申请后，按当前业务数据恢复相应待办。
- 通知已读状态不代表业务完成，不提供手工清除这些待办的按钮。

## 权限、公司与刷新

- 保留库房工作台能力和公司范围检查；新增采购提示还检查采购能力和所需单据读取权限。
- 采购申请和采购订单沿用原列表权限及完整单据权限检查。
- 单公司模式的数量和按钮使用明确的公司参数；全部公司模式按公司分别展示，避免汇总数量跳往默认公司。
- 缺料仍遵循现有缺料页按可见销售/生产需求计算的权限口径，不改变其库存规划算法。
- 新增订单、生产计划、BOM、制造设置和采购分配变化对库房刷新主题的通知，复用现有页面刷新与过期版本重查。
- 两个读接口由同一页面加载器管理，防止旧公司/旧筛选响应覆盖新选择。业务计算失败不会被伪装成“暂无待办”；网络请求失败会显示更新失败并保留重试状态。
- 缺料页返回同公司时保留手工采购数量和勾选；切换公司清空旧搜索并重新读取。

| 场景 | 结果 |
| --- | --- |
| 提交销售订单、存在缺口但无库存草稿 | 出现缺料待处理 |
| 提交采购申请覆盖缺口 | 缺料消失，申请待跟进出现 |
| 创建采购草稿 | 申请仍待跟进 |

| 取消部分采购单 | 剩余待下单恢复 |
| 取消采购申请 | 缺料恢复 |
| 不同业务阶段同时存在 | 两项新提示与原采购待收货同时正确显示 |

真实角色检查 5 项通过：库房角色公司范围、外公司拒绝、受限仓库单据过滤、缺少公司范围拒绝、纯销售角色拒绝。成品仓范围账号的需求缺料汇总与原缺料页一致，原料采购申请和采购单依然受原生仓库单据权限约束。

- 多公司分组、失败空态及公司切换覆盖由自动化测试验证。

自动刷新实页验证：库管保持独立预览站点的工作台打开；通过原生流程取消未关联后续单据的种子销售订单后，缺料卡片自动消失，采购跟进和采购待收货均保留。随后正常新建并提交等量销售订单，缺料卡片自动恢复为 1 项物料、1 张订单。两次观察均未点击刷新或重新导航。

隔离预览入口：`http://hs-wb-actions.localhost:18093/desk/warehouse-workbench`。独立连接探针验证合法同源连接通过、伪造 Origin 被拒绝；内置浏览器曾报告 Socket.IO Origin 错误，因此上述实页结果证明自动更新可用，不单独归因为 WebSocket 推送，包含版本重查的兜底路径。
