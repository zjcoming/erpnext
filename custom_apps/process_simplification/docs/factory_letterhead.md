# 工厂简洁表头

最新版本已扩展五类默认打印与库存扫码，安装 / 升级和后台 PDF 行为以 [工厂默认打印与库存扫码](factory_print_suite.md) 为准。以下保留此前实现及验证记录。

在安装或迁移 `process_simplification` 时新增“工厂简洁表头”，在组织 → 打印表头中管理，在单据打印预览中选择。

公司名称居中，地址与联系方式紧凑排布，底部采用黑色双横线。Logo 有设置时显示；采购订单和 Job Card 在右上方显示 28 mm 黑白二维码、“仅限系统内扫码”及可读单号。二维码不包含系统访问地址。单据标题、业务表格和签字栏由原打印格式负责。扫码规则见 [单据扫码说明](document_scan.md)。

## 信息来源

- 公司：当前单据的 `company`；打印 Company 本身时使用其 `name`。不使用软件厂商名称，不猜测没有所属公司的单据。
- 名称、Logo、电话、邮箱、网址：Company 的对应字段。打印时读取，修改公司资料后无需重新生成表头。
- 地址：只选取关联到该公司的启用地址。单据 `company_address` 在其中时优先使用，否则取公司主地址；不使用客户/供应商的 `billing_address`。
- 电话和邮箱：Company 未填写时，使用选定公司地址的电话和邮箱。其余空项自动隐藏。

## 安装及维护

`after_install` / `after_migrate` 先初始化持久系统标识，再自动补建表头。仅对内容哈希与本应用最初模板、旧网址码模板完全一致的 HTML 表头升级二维码；用户改过的内容、禁用状态和现有默认表头均保留。没有默认表头时才将新增表头设为默认。用户可以在“工厂简洁表头”中自行勾选默认，或在单据打印时单独选择。

旧网址码已停用，之前的 PDF 和纸质单据需要重新打印。已经使用 `get_document_scan_qr` 的自定义表头会生成新内部码，其自定义说明文字保留，需自行调整为“仅限系统内扫码”。

打印页默认中文。采购订单 / Job Card 原本选中原生 `Company Letterhead`、`Company Letterhead - Grey` 或未设置表头时，预览优先选择已启用的“工厂简洁表头”；已有其他自定义表头继续使用。此行为只影响预览选择，不修改单据或数据库中的默认表头。中文模板、金额大写和弹窗说明见 [打印中文默认行为](print_localization.md)。

模板文件：`process_simplification/templates/print/factory_letterhead.html`。它是完整的 Header HTML，含作用范围受限的 CSS，也可在已安装本应用的站点上用于手工创建 HTML 表头；二维码函数通过本应用的 Jinja hook 提供。管理员修改已保存的表头后，后续迁移保留其修改。

表头与扫码 Python 测试共 26 项通过，覆盖公司切换、地址归属、分厂地址优先、缺失字段、HTML 转义、默认表头保护、内部二维码生成与权限。最初无二维码版本的完整资料、仅名称、长名称与 Logo 浏览器预览已检查。

2026-09-11 已在 `development.localhost` 启用，保留默认的 `Company Letterhead - Grey`。现有采购订单及 Job Card 的原生打印 HTML / wkhtmltopdf PDF 均已生成并从 PDF 渲染图解码核对。二维码采用 PNG，避免本地 wkhtmltopdf 对 SVG 的输出失真。

内部码切换后再次生成采购单 1 页、Job Card 2 页，三页均解码出正确且不含网址的单据码；“仅限系统内扫码”说明及中文表头已目视检查。

开发容器已补装 `fonts-noto-cjk`，中文 PDF 字形已目视检查；生产镜像 Dockerfile 同步加入字体依赖，但尚未构建或发布新生产镜像。开发容器重建使用原始 bench 镜像时需要重新安装字体。实际纸张扫码、全部自定义打印格式，以及带二维码的长公司名 / Logo 组合仍需现场复核。
