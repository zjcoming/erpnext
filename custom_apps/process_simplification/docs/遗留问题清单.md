## PS-001 历史完工数量被当作当前可回补数量

### 现象

销售订单 `SAL-ORD-2026-00004` 的历史生产工单 `MFG-WO-2026-00004` 已完成 511 件，但当前成品可用库存为 0、有效预留为 0、订单仍待交 511 件。生产工作台同时显示：

- 已完工：511
- 待回补：511
- 需要生产：511
- 未安排：511

“待回补 511”容易让用户误以为当前仍有 511 件成品可以回补给订单。

### 已确认根因

当前 `process_simplification/api/workbench.py` 按以下口径计算：

```text
待回补数量 = 关联工单历史完工数量 - 已通过完工入库单预留给本订单的数量
```

该计算没有结合当前可用成品库存，因此历史完工成品即使已经被其他订单交货、预留、调拨或通过其他库存交易消耗，仍会被计入“待回补”。

### 期望结果

- “历史已完工”和“当前可回补”必须分开显示和计算。
- 当前可回补数量应受实际可用成品库存限制。
- 当前可回补数量为 0 时，应隐藏或禁用“回补订单”操作。
- 页面应突出显示当前生产缺口 511，而不是突出历史待回补数量。

### 回归验证

1. 为销售订单生产并完成 511 件，但不预留给原订单。
2. 使用其他订单或库存交易消耗这 511 件成品。
3. 刷新生产工作台。
4. 确认历史已完工仍为 511，但当前可回补为 0、生产缺口为 511，且不能执行回补。

## PS-002 补产工单被 ERPNext 原生超产校验阻止提交

### 现象

针对 `SAL-ORD-2026-00004` 重新创建 511 件多级生产任务后，成品主工单 `MFG-WO-2026-00013` 提交失败：

```text
Cannot produce more Item ... than Sales Order quantity 511.0 Nos
```

### 已确认根因

ERPNext 原生工单提交校验会累计同一销售订单、同一成品下所有“已提交且未关闭”的生产工单数量：

```text
原工单 511 + 新补产工单 511 = 累计计划生产 1,022
销售订单数量 = 511
允许超产比例 = 0%
```

因此新工单被判定为超订单生产。该原生校验不考虑原工单生产的成品当前是否仍在库或是否已被其他订单消耗。

### 设计要求

- 为“历史成品已被消耗后重新生产”的场景建立明确的补产工单语义。
- 补产工单仍需保留销售订单明细级业务追踪。
- 不应通过全局提高“销售订单允许超产比例”绕过校验，否则所有订单都会获得超产权限。
- 优先在 `process_simplification` 自定义应用中解决，不修改 ERPNext 核心代码。
- 方案需要同时兼容生产计划生成的成品工单和多级半成品工单。

### 回归验证

1. 原订单已有一张完成 511 件的生产工单。
2. 原完工成品已不在可用库存，订单仍待交 511 件。
3. 从生产工作台创建 511 件多级补产任务。
4. 成品主工单及各级半成品工单均可按正确顺序提交。
5. 工作台将成品主工单计入 511 件工单覆盖，不将半成品工单重复计入成品覆盖。
6. 其他普通销售订单仍受原生超产限制。

## PS-003 生产计划生成草稿工单后，工作台仍显示“待安排”且缺少提示

### 现象

通过生产计划成功生成多级生产工单后，生产工作台仍显示：

- 工单覆盖：0
- 未安排：511
- 状态：待安排

用户容易判断为生产工单没有关联成功。

### 已确认事实

- `MFG-WO-2026-00013` 至 `MFG-WO-2026-00018` 均已关联销售订单、销售订单明细和生产计划。
- 上述工单均为草稿，`docstatus = 0`。
- 工作台只将已提交工单 `docstatus = 1` 计入工单覆盖，这是合理的数量控制，但页面没有解释草稿工单不计入覆盖。

### 期望结果

- 创建完成后明确提示“已生成草稿生产工单，提交后才计入生产安排”。
- 工作台可增加“待提交工单”状态或草稿工单数量。
- 关联任务区域可展示草稿工单，但必须与已提交工单明显区分。
- 草稿工单不得提前占用正式工单覆盖数量。

### 回归验证

1. 从工作台创建多级生产任务。
2. 未提交时能够看到草稿工单及明确提示，但正式工单覆盖仍为 0。
3. 提交成品主工单后，工单覆盖更新为对应数量，未安排数量同步减少。

## PS-004 “待回补订单”状态无法区分可回补和必须补产

### 现象

以下两种业务状态目前都可能出现“待回补”相关数量或操作：

1. 成品已完工并且仍有可用库存，只是尚未预留给销售订单。
2. 历史上已经完工，但成品已被其他业务消耗，当前没有库存可以回补。

第二种情况实际上应该重新生产，不应继续表达为“待回补订单”。

### 期望结果

- 有可用成品且尚未预留时：显示“成品已完工，待预留到订单”。
- 无可用成品且订单仍待交时：显示“成品已消耗，待补产”或“待重新生产”。
- 状态颜色应区分“生产已完成后的订单预留动作”和“存在生产缺口的风险状态”。
- 状态、数量和可执行按钮必须保持一致。

### 回归验证

分别构造“有库存可回补”和“无库存必须补产”两个订单，确认状态文案、颜色、数量及操作按钮不会混用。

## PS-005 无法从工作台追溯已完工成品的实际去向

### 现象

工作台能够显示历史完工数量和当前可用库存，但无法直接解释历史完工成品为什么已经不可用。用户无法判断成品具体是：

- 被其他销售订单交货；
- 被其他订单预留；
- 被调拨到其他仓库；
- 被库存调整或其他出库交易消耗。

### 设计要求

- 提供“查看成品去向”或等价追溯入口。
- 至少展示完工入库单、库存预留、交货单和相关库存流水。
- 明确区分已确认的单据关系与仅根据库存变化作出的推断。
- 不改变 ERPNext 原生库存数量归属，仅增强追溯展示。

### 回归验证

使用交货、调拨、预留和库存调整分别消耗完工成品，确认工作台能定位实际单据和数量。

## PS-006 多级生产工单提交后的关联展示与数量口径尚未完成验证

### 当前情况

生产计划 `MFG-PP-2026-00002` 已生成：

- 成品主工单：`MFG-WO-2026-00013`
- 多级半成品工单：`MFG-WO-2026-00014` 至 `MFG-WO-2026-00018`

所有工单均已写入销售订单明细关联，但由于 PS-002 阻止成品主工单提交，尚未完成提交后的工作台验证。

### 待验证内容

- 关联生产任务能否完整展示成品和各级半成品工单。
- 层级关系、生产顺序及状态是否清晰。
- 只有成品主工单计入销售订单成品工单覆盖。
- 半成品工单不得导致销售订单成品覆盖重复累计。
- 任一级工单取消、关闭或部分完成时，工作台数量能否正确更新。

## 修复原则

- 订单能否开工、是否需要补产，应以当前订单需求、有效预留、当前可用库存和有效工单覆盖共同判断。
- 历史累计数量不能直接替代当前可执行数量。
- 共享库存的实际所有权继续由 ERPNext 原生库存和预留单据管理；自定义字段只用于业务追踪和工作台展示。
- 不通过修改 ERPNext 核心代码或放宽全局超产比例解决单一补产场景。
- 每个问题修复前先补充失败测试，修复后同时验证单订单、多订单争用库存和多级生产场景。
