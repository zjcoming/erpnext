# 采购拒收闭环：规则与验收

本文范围是恒算 ERP 的采购入库拒收、生产缺料判断、拒收品退回、补送或补采，以及再次收货后的待办关闭。业务库存仍由原生 Purchase Receipt / Purchase Return 提交记账。未完成的表格不能作为验收通过证明。

## 必须成立的业务规则

1. 到货 700、合格 600、拒收 100，应使原材料仓增加 600、拒收仓增加 100。拒收仓数量不能满足合格生产需求。
2. “供应商已送到”“合格物料已到齐”“拒收品已处理”是三个不同状态。原生采购订单按总到货量显示收货完成时，尚未退回的拒收品仍须有可见待办和下一步入口。
3. 拒收不自动生成采购申请、采购订单或库存移动。系统应显示当前需处理的拒收品，并让授权库管进入退货；补送或补采按当前需求与已有供应确定，不能重复安排采购。
4. 退回拒收的 100 不减少此前已入合格仓的 600。通知、采购申请净合格收货进度、缺料与采购待办须采用一致的数量含义。
5. 退回合格品才减少净合格收货。混合退货须分别识别合格退回和拒收退回；不得简单把整行退货数量都从合格进度扣除。
6. 供应商补送合格品后，原申请的净合格进度、生产齐套和待办应随已提交单据更新。若改向其他供应商补采，要保留源需求关系或明确告知原申请未回填，不得把未到货的申请永远算作未来供应。
7. 另有库存或另一张采购收货覆盖生产需求时，可以不再缺料；拒收品的实物处理待办仍须保留至退回或其他明确处置完成。两个待办不能相互抵销。
8. 草稿、取消的收货/退货、通知是否已读均不能改变已提交库存事实。撤销退货后须恢复拒收待办和正确进度。
9. 只让具备公司、仓库、源收货单访问权限的用户查看和处理；不能依赖前端隐藏按钮保护写接口。生产主管通知可为只读摘要，无收货权限时不得获得采购写权限。
10. 刷新、重试、重复点击、两个库管并发不得造成重复退货草稿、超量退回、重复补采或重复通知。后台失败不能显示为“无待办”。

## 一个可复现的基准流程

同一公司、同一需求行申请 700 克；初始两仓均为零；原材料仓与拒收仓分别建立，拒收仓勾选“是拒收仓”；无额外在途供应和其他订单。

| 步骤 | 合格仓 | 拒收仓 | 原申请净合格 / 尚缺 | 业务上应出现的动作 |
|---|---:|---:|---:|---|
| 采购订单提交 700 | 0 | 0 | 0 / 700 | 等待原采购到货，避免重复采购 |
| 入库提交：合格 600、拒收 100 | 600 | 100 | 600 / 100 | 拒收品待处理；核对补送或补采，不得称生产已齐套 |
| 创建拒收退货草稿 100 | 600 | 100 | 600 / 100 | 继续核对退货草稿；库存和实物待处理量尚未减少 |
| 提交拒收退货 100 | 600 | 0 | 600 / 100 | 拒收实物待办关闭；若原 PO 可补送则显示待补送 100 |
| 提交合格补送 100 | 700 | 0 | 700 / 0 | 本行齐套，采购跟进与拒收待办关闭 |
| 撤销补送 | 600 | 0 | 600 / 100 | 再次出现相应等待到货/缺料状态 |

这里“尚缺”是原申请的净合格未到数量。生产页面的缺料数量还要结合有效库存、已下达需求、其他供应与分配顺序计算，不能直接等同为每一次都需要新采购 100。
