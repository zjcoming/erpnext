# 生产工作台按交期分配物料设计

## 目标

生产工作台必须回答某一条销售订单需求当前是否具备开工条件，而不是把公司全部生产需求的汇总缺口复制到每张订单。采购缺料页面继续保留跨订单汇总口径，用于合并采购。

## 业务口径

- 分配对象是 `Sales Order Item.name` 对应的生产需求。
- 分配范围按公司、生产原料仓和物料编码隔离，不跨公司、跨仓库借料。
- 优先顺序为产品交期升序；同交期按销售订单创建时间、销售订单号、销售订单行标识稳定排序。
- 缺少交期的需求仍显示高风险，但排在有交期需求之后，避免无日期订单抢占已承诺交期订单的物料。
- 较早需求按完整 BOM 需求优先占用共享物料；即使它自身仍缺少其他组件，也不把已优先分配的组件自动让给较晚订单。
- 分配是工作台实时计算的软分配，不创建新的库存台账或自定义预留单据。

## 库存与供应分配

1. 每个需求使用有效 BOM 和当前生产需求数量展开原料。
2. 当前可用库存按优先顺序只分配一次。
3. 已提交 Purchase Order 和 Material Request 的未完成数量也按优先顺序只分配一次。
4. 供应单据只有在其计划日期不晚于本需求交期时，才可以覆盖本需求；晚到单据保留为提示，但不能使本单变成已覆盖。
5. 先分配已提交 Purchase Order，再分配 Material Request，以保持“待收货”比“待下单”的供应确定性更高。
6. 每张订单仍显示物料的公司级总需求，另行显示本需求数量、本次可用库存、本单获配在途数量、即时缺口和新增采购缺口。

## 状态

- `可开工` 只适用于已有未开始 Work Order，且每种原料的即时缺口都为零的需求。
- 当前库存不足但在途或采购申请能够按交期覆盖时，物料摘要显示 `待到料`，不能显示 `可开工`。
- 当前库存和按期供应仍不能覆盖时，物料摘要显示 `缺料`，并保留“处理缺料”动作。
- 尚未创建 Work Order 的需求继续以 `待安排` 为主状态；物料摘要独立说明其是齐套、待到料还是缺料。
- 已开始生产的 Work Order 不因工作台重算而回退生产状态，但物料摘要仍显示其后续用料风险。

## 代码边界

- 只修改 `custom_apps/process_simplification`。
- 复用现有 BOM 展开、库存快照、Material Request、Purchase Order 和 Work Order 查询。
- `calculate_material_coverage` 继续作为单组需求覆盖计算器；新增生产工作台顺序分配编排，不改变 `check_all_shortages` 的采购大池汇总。
- 不修改 ERPNext/Frappe 官方代码，不新增持久化分配表，不自动创建采购或库存单据。

## 错误处理

- BOM 展开失败或原料仓不可用时，沿用现有 `master_data_blocked` 处理。
- 单个公司计算异常不能产生部分持久化结果，因为本功能只读；页面按现有错误机制提示刷新或修复资料。
- 每次刷新重新读取库存、供应单据和订单状态，结果附带 `checked_at` 时间。

## 验收标准

- 两张订单共享一份只能满足一张订单的库存时，较早交期订单显示现货齐套，较晚订单显示缺料。
- 同交期需求按创建时间和订单标识稳定分配，输入顺序变化不影响结果。
- 同一份 Purchase Order 或 Material Request 未完成数量不能同时覆盖两张订单。
- 晚于早期订单交期、但早于后期订单交期的供应，只能覆盖后期订单。
- 已有未开始 Work Order 且现货齐套时显示 `可开工`；只有在途覆盖时不得显示 `可开工`。
- 采购缺料汇总仍按全部开放生产需求合并计算，不受生产工作台逐单展示影响。

## 非目标

- 不做产能、设备、人员或工序排程。
- 不做原料硬预留、自动领料或自动开工。
- 不提供人工拖拽优先级；如交期排序不能满足经营需要，再单独增加老板优先级。
- 不改变合并采购和供应商选择规则。
