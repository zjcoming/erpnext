# 订单履约总览设计说明

## 目标

为小型制造企业老板提供一个跨销售订单的履约总览：默认展示全部尚未交付完成的销售订单，按最早交期优先排列，让用户快速判断哪些订单已逾期、临近交期、可直接发货、需要生产、生产进行中或存在基础资料风险。

该页面定位为“订单履约总览”，不是“生产工作台”。库存足够、无需生产、可直接发货的订单仍属于待履约订单，必须展示；未来独立的生产工作台只承载生产需求和生产执行，不展示纯发货订单。

## 已确认的页面结构

- 一级粒度：销售订单。一张订单占一行，老板先看交期和整体风险。
- 二级粒度：销售订单明细。展开订单后展示产品级数量、库存预留、生产覆盖、未覆盖量、状态和可执行动作。
- 默认排序：最早待交日期升序，其次风险严重度降序，再按订单创建时间升序。
- 顶部指标：未完成订单、已逾期、7 天内交付、需要生产、可直接发货。
- 筛选：订单号/客户/产品搜索、履约状态、交期范围、客户、只看有风险。
- 订单摘要：订单号、客户、最早交期、交付进度、库存覆盖、生产进度、最大风险和下一步。
- 展开明细继续复用现有预留库存、创建生产任务、查看生产任务、预留完工成品、创建发货单草稿等动作。

## 数据来源与计算边界

ERPNext 标准单据是唯一事实来源，不新增履约台账：

- `Sales Order` / `Sales Order Item`：订单、客户、交期、订购量、已交付量。
- `Stock Reservation Entry`：当前销售订单明细的有效成品预留量。
- `Work Order`：订单明细对应的生产覆盖和生产进度。
- `Stock Entry`：完工数量及完工后待预留判断。
- `Delivery Note`：通过销售订单明细的已交付数量间接反映交付进度。

总览接口复用现有 `get_order_workbench` 的逐行权威计算，不复制库存、预留、生产或发货业务规则。页面加载和每次简化动作完成后重新读取标准单据。

## 纳入与排除规则

纳入：用户有权读取、已提交、未关闭且未全部交付的销售订单。

排除：草稿、已取消、已关闭、已全部交付的销售订单。某张订单若头部状态未及时更新，但所有明细待交数量均为零，也在聚合后排除。

快速开单创建的订单与标准销售订单采用同一规则。库存完全覆盖的订单显示为“可直接发货”，不会因为无需生产而从总览消失。

## 交期规则

- 订单只有一个待交日期时直接显示该日期。
- 标准销售订单存在多个明细交期时，订单行显示最早的未完成明细交期，并提示“多交期”。
- 缺少交期的订单排在有交期订单之后，但标记“缺少交期”，属于需关注风险。
- 交期比较使用站点当前日期；小于当前日期为逾期，等于当前日期为今日交付，未来 7 天内为临期。

## 履约与风险状态

订单级状态由明细实时聚合，并且只展示一个最高优先级结论：

1. 已逾期。
2. 基础资料/简化动作不支持，例如重复成品行或缺少可用 BOM。
3. 临期且仍有未覆盖生产需求。
4. 需要生产但尚未被生产任务覆盖。
5. 生产中。
6. 库存仅部分覆盖。
7. 全部待交数量已被有效预留，可直接发货。
8. 一般待处理。

“缺料”只有在执行了权威 BOM 缺料检查后才能宣称具体项数。总览首屏不自动展开全部 BOM，避免每次进入页面产生高成本查询；尚未检查时显示“物料待检查”，并提供进入缺料检查的动作。

## 操作边界

- 总览读取不创建或提交任何业务单据。
- 展开后的明细动作调用现有服务端 API；服务端在写入前继续重新检查权限、库存预留、未覆盖数量和标准单据状态。
- 发货仅创建 Delivery Note 草稿，仓库人员核对实物后在 ERPNext 中提交。
- 总览不自动生成采购单、不自动提交生产或发货单据。
- 页面可以导出当前筛选后的可见摘要，但导出不是业务事实来源。

## 边界案例

- 同一销售订单多个相同成品行：都展示，但沿用现有“不支持简化动作”保护，避免错误聚合。
- 一张订单同时包含可发货和需生产产品：订单显示最高风险，展开后逐产品处理。
- 部分发货：交付进度使用已交付/订单总量，剩余需求继续参与库存与生产计算。
- 部分预留、部分生产：库存覆盖和生产覆盖分别展示，不把在制品当作可发货库存。
- 完工未预留：显示完工待预留，不把该库存默认归属于订单。
- 无 BOM 的库存商品：库存足够时仍可发货；库存不足时显示缺少生产基础资料，不自动创建生产任务。
- 外部用户取消预留、生产任务或发货单：下次刷新按标准单据重新计算。
- 大量历史未完成订单：首版以小公司数据规模为边界，读取全部未完成订单；后续只有在真实性能数据表明需要时再增加分页或后台快照，不预建新的履约台账。

## 非目标

- 不把页面扩展为生产排程、产能排班或甘特图。
- 不实现自动采购决策和自动提交采购单。
- 不修改 ERPNext 核心 DocType、控制器或数据库逻辑。
- 不替代标准销售订单、生产任务、库存预留和发货单页面。

## 验收标准

- 打开页面即可看到全部未完成订单，并按最早交期优先排序。
- 同交期订单按风险严重度排序。
- 可直接发货且无需生产的订单仍出现在总览中。
- 展开订单可看到销售订单明细粒度的履约数量和现有动作。
- 顶部五个指标按订单计数，且与当前加载结果一致。
- 搜索与筛选不会改变后端事实，只改变当前可见集合。
- 刷新或执行动作后从 ERPNext 标准单据重新计算。
- 所有新增代码位于 `custom_apps/process_simplification`，ERPNext 核心无改动。
