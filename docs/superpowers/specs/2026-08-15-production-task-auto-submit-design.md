# 生产工作台生产任务自动提交设计

## 背景

生产工作台的“创建生产任务”当前通过 ERPNext 生产计划引擎生成成品生产工单和多级半成品生产工单，但生产计划与生产工单均停留在草稿状态。生产工作台只将已提交生产工单计入工单覆盖，因此用户完成创建后仍看到“待安排”，并误认为生产任务没有关联成功。

## 目标

- 点击“创建生产任务”并确认后，生产计划、成品主工单和所有多级子工单均直接提交。
- 仅在全部单据提交成功后向前端返回成功。
- 任意一步失败时整批回滚，不保留草稿、部分已提交工单或半套多级生产任务。
- 成功后，已提交成品主工单立即计入订单的工单覆盖；多级子工单保留订单与生产计划追踪，但不重复计入成品覆盖。

## 不在本次范围

- 不绕过 ERPNext 原生销售订单超产校验。
- 不处理“历史完工成品已被其他订单消耗后再次补产”的超产冲突；该场景继续按遗留问题 PS-002 单独设计。
- 不改变工作台仅将已提交工单计入正式工单覆盖的原则。
- 不修改 ERPNext 或 Frappe 核心代码。

## 选定方案

采用完整的 ERPNext 单据生命周期：

```text
校验创建及提交权限
  -> 新建并保存生产计划
  -> 展开多级半成品并再次保存生产计划
  -> 提交生产计划
  -> 使用生产计划生成全部生产工单
  -> 提交成品主工单及全部多级子工单
  -> 返回已提交单据并刷新生产工作台
```

生产计划必须先保存展开后的子装配明细再提交，避免已提交生产工单引用未持久化的生产计划子表行。

## 原子性与错误处理

- 创建链路开始前建立数据库保存点。
- 生产计划保存、提交、工单生成或任一工单提交失败时，回滚到该保存点并继续抛出原始业务异常。
- 前端只在接口成功返回后显示创建成功并刷新工作台。
- 失败消息保留 ERPNext 的具体校验原因，例如仓库缺失、权限不足或销售订单超产，不用笼统的“创建失败”覆盖根因。
- 不允许“部分工单已提交、其余工单仍为草稿”的结果。

## 权限边界

- 操作人必须具有生产计划的创建和提交权限，以及生产工单的创建和提交权限。
- 不使用 `ignore_permissions` 绕过提交权限。
- 权限不足时在创建任何持久化单据前失败。

## 工单提交与返回值

- 提交生产计划引擎生成的全部生产工单，不只提交成品主工单。
- 工单列表继续按生产计划引擎生成顺序返回；成品主工单仍作为接口返回的 `work_order` 主入口。
- 接口额外保证返回的 `work_orders` 全部为已提交状态。
- 前端现有成功回调继续刷新生产工作台，无需新增第二次“批量提交”操作。

## 测试设计

### 单元测试

- 生产计划展开多级明细后会保存并提交，再调用工单生成引擎。
- 所有生成工单都会调用提交。
- 任一工单提交失败时执行保存点回滚并继续抛出原异常。
- 权限不足时不创建生产计划。
- 返回结果只包含已提交的工单名称。

### 集成测试

- 单层 BOM：接口成功后生产计划和成品工单均为已提交状态。
- 多级 BOM：生产计划、成品主工单及所有需要自制的子工单均为已提交状态。
- 工作台刷新后成品主工单计入工单覆盖，未安排数量相应减少；半成品工单不重复累计成品覆盖。
- 人为制造其中一张工单提交失败，确认生产计划和整批工单均未留存。
- 触发原生超产校验时整批回滚，且错误原因原样返回。

## 验收标准

1. 正常订单点击一次“创建生产任务”即可得到完整的已提交多级生产任务。
2. 工作台刷新后不再因草稿状态显示“工单覆盖 0”。
3. 数据库中不存在由失败请求遗留的草稿生产计划或生产工单。
4. 原生权限、仓库、BOM 和超产校验继续生效。
5. 相关单元测试、集成测试及现有 `process_simplification` 回归测试通过。
