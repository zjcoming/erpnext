# 快速开单物料风险前置设计

## 1. 目标

快速开单不仅要告诉老板“成品够不够”，还要在确认销售订单前解释：

- 本单需要多少成品；
- 当前成品仓库中有多少账面库存、多少已经被其他需求预留、本单当前可使用多少；
- 剩余数量需要生产多少；
- 按本次选定产品的 BOM，生产所需的每项物料是多少；
- 各物料当前可使用库存、已有采购覆盖和预计采购缺口分别是多少；
- 哪些问题只是交期风险，哪些问题导致系统无法可靠计算并必须阻止下单。

目标是让老板在接单前看清风险，但不把库存预留、生产任务和采购执行塞进快速开单。ERPNext 标准单据继续作为销售、库存、生产和采购的唯一事实来源。

## 2. 产品边界

采用“信息前置、动作后置”的分层设计。

### 快速开单

负责回答“这张订单能不能接、可能面临什么履约风险”。页面显示只读的成品覆盖、生产需求、BOM 用料覆盖和预计采购缺口，不创建库存预留、Work Order、Material Request 或 Purchase Order。

### 订单工作台

负责销售订单成立后的订单级执行。重新读取标准 ERPNext 单据，展示实际预留、生产覆盖和最新缺料，并提供预留成品、创建生产任务和处理缺料的入口。

### 缺料采购页面

负责采购需求执行。它可以汇总一张或多张销售订单的原料缺口，允许确认建议数量，并创建标准 ERPNext `Material Request`，类型为 `Purchase`。供应商、价格、税费和正式 `Purchase Order` 继续走 ERPNext 标准采购流程。

## 3. 页面信息架构

保留现有订单信息、产品明细和底部汇总栏。在产品明细与底部汇总栏之间新增“生产与物料风险”区域。

### 3.1 产品行摘要

每个产品行继续显示紧凑状态：

```text
订单 400 | 本单可用成品 311 | 需生产 89 | BOM 已就绪 | 预计缺料 3 项
```

状态文案分为：

- `库存可覆盖`：本单数量全部可由当前可预留成品覆盖；
- `需要生产`：成品不足，但存在可用 BOM；
- `预计缺料`：生产所需原料存在净采购缺口；
- `无法计算`：缺少仓库、有效 BOM 或其他必要主数据；
- `待重新检查`：影响计算的订单内容已经变化；
- `检查中`：正在执行服务器深度检查。

“需要生产”和“预计缺料”不是同一概念。需要生产但原料充足时，缺料项应为零。

### 3.2 页面下方的 BOM 物料区域

深度检查成功后，按销售产品分组显示。每个产品形成一个卡片或折叠区：

```text
产品：CFCG125-12脚……
订单数量：400  本单可用成品：311  需生产：89
成品仓库：成品仓 - 恒  BOM：BOM-CFCG125-001
```

卡片内显示该产品生产需求对应的 BOM 物料行：

| 字段 | 说明 |
| --- | --- |
| 物料 | 物料编码、名称和库存单位 |
| BOM 单耗 | 生产一个 BOM 基准数量对应的用量 |
| 本次需求 | 按该产品需生产数量展开后的物料毛需求 |
| 来源仓库 | BOM、物料或公司默认解析出的原料仓库，只读 |
| 账面库存 | 检查时点的仓库实际库存 |
| 已占用/预留 | 已被其他有效需求占用、不能再用于本单的数量 |
| 本单可用 | `max(账面库存 - 已占用/预留, 0)` |
| 未下单采购申请 | 已提交但尚未转成采购订单的有效采购申请余额 |
| 按时在途采购 | 已提交且预计在本单需求日期前到货的采购订单未收货量 |
| 当前生产缺口 | 本次需求扣除本单可用原料后，当前还不能直接投产的数量 |
| 建议新增采购申请 | 扣除有效采购流程后，当前仍需新增申请的数量 |
| 结论 | `当前可生产`、`待采购到货`、`已提采购申请`、`需新增采购`或`无法判断` |

只要有缺料，该产品卡片默认展开；所有原料充足的产品可以默认折叠，但仍允许老板查看完整 BOM 用料。页面不能只返回缺料行，否则“缺料 0 项”仍然无法解释为什么原料足够。

同一种原料被多个产品使用时：

- 产品卡片内显示该产品对原料的需求贡献；
- 页面下方增加一份“本单预计采购汇总”，按物料和仓库聚合后只计算一次缺口；
- 不把不同库存单位的原料数量相加为一个总数量，只显示缺料物料项数。

### 3.3 底部汇总栏

保留订单金额、可预留成品、需生产数量、缺料项和最近检查时间。缺料状态允许点击并定位到“生产与物料风险”区域。

确认窗口显示：

- 成品覆盖数量；
- 需生产数量；
- 预计缺料项数；
- 缺料物料摘要；
- “销售订单提交不会自动预留库存、创建生产任务或采购申请”的说明。

## 4. 计算口径

### 4.1 成品覆盖

对每个产品和解析出的成品仓库：

```text
本单可用成品 = min(订单数量, ERPNext 当前可预留数量)
需生产数量 = max(订单数量 - 本单可用成品, 0)
```

当前可预留数量必须使用 ERPNext 的库存预留语义，不得以仓库账面库存直接替代。

### 4.2 BOM 物料需求

只有需生产数量大于零的产品才展开生产物料。使用预检时确定的已提交、启用、默认 BOM，并按需生产数量展开多级 BOM。

快速开单不允许老板临时选择替代 BOM。没有有效默认 BOM 时，系统无法可靠承诺生产，必须阻止确认并引导维护 BOM 或使用标准流程。

### 4.3 原料覆盖与采购缺口

每个物料必须按公司、来源仓库、库存单位和需求日期计算：

```text
本单可用原料 = max(账面库存 - 已占用或预留数量, 0)

当前生产缺口 = max(
  本次 BOM 毛需求
  - 本单可用原料,
  0
)

建议新增采购申请 = max(
  本次 BOM 毛需求
  + 适用的安全库存补足量
  - 本单可用原料
  - 有效且尚未下单的采购申请余额
  - 能在需求日期前到货的采购订单余额,
  0
)
```

采购申请余额与采购订单余额必须互斥：采购申请已经转成采购订单的部分，只计入采购订单余额，不能重复扣减。

未下单的采购申请只用于避免重复提出采购需求，不代表物料已经获得供应保障。页面必须把它标记为“已提申请、尚未下单”，不能因此显示“原料充足”。只有本单可用原料足够时才能显示“当前可生产”；采购订单按时在途时显示“待采购到货”。

采购订单只有在公司、目标仓库和物料一致，并且预计到货日期不晚于生产需求日期时，才能被标记为“按时覆盖”。晚到采购单单独显示为风险，不能把缺口显示为零。

第一阶段若无法可靠获得安全库存、采购倍数或生产需求日期，则安全库存补足量默认为零，采购数量按库存单位给出“预计缺口”，不声称是最终下单数量。

## 5. 查询和确认时机

### 轻量预览

产品或数量稳定输入后自动执行，只查询产品、价格默认值、成品仓库、当前可预留成品、需生产数量和 BOM 是否可用。不在每次键盘输入时展开 BOM。

### 显式深度检查

点击“检查库存与缺料”后，按整张订单执行：

- 重新检查成品可预留数量；
- 固定本次用于判断的 BOM 候选；
- 展开全部需生产产品的 BOM；
- 计算全部物料覆盖和预计采购缺口；
- 返回产品分组明细和订单级采购汇总；
- 记录检查时间和可供确认的检查令牌。

### 修改失效

客户、交付日期、产品、数量或价格变化后，深度检查结果立即标记为过期。旧明细可以保留用于视觉连续性，但必须明确显示“数据已变化，待重新检查”，且不能作为最终确认依据。

### 提交前复查

打开确认窗口前执行权威预检；最终提交前再次在服务器计算。如果成品覆盖、需生产数量、BOM、缺料状态或商业校验结果发生实质变化，则不创建销售订单，刷新风险信息并要求老板重新确认。

## 6. 警告和阻断规则

### 允许继续下单的警告

- 成品库存不足，需要生产；
- 原料存在预计采购缺口；
- 在途采购晚于生产需求日期；
- 可用库存发生减少，需要老板重新确认新的履约风险。

这些情况代表经营决策，不应自动阻止老板接单。

### 必须阻断

- 无法确定公司、成品仓库或原料来源仓库；
- 需要生产但没有有效默认 BOM；
- BOM 循环、损坏或无法展开；
- 产品、数量、单位、价格或交付日期无效；
- 不支持的产品组合、变体、批次/序列号、委外或客户供料场景；
- ERPNext 权限、客户、信用或标准销售订单校验失败。

## 7. 执行动作

快速开单不得提供“立即采购”按钮。销售订单成功创建后进入订单工作台，并重新读取标准单据和最新库存：

1. 预留当前仍可用的成品；
2. 为未覆盖数量创建与 Sales Order Item 关联的 Work Order；
3. 点击“处理缺料”进入缺料采购页面；
4. 按最新缺口和多个订单的聚合结果生成标准采购申请；
5. 采购人员从采购申请进入标准 ERPNext 采购订单流程。

如果未来具备完整的首选供应商、采购价、交期、最小起订量和包装倍数，可以新增“按供应商生成采购订单草稿”，但不属于本次范围，也不得自动提交采购订单。

## 8. 技术边界与复用

- 不修改 ERPNext 核心；
- 继续使用标准 `Sales Order`、`Sales Order Item`、`BOM`、库存预留、`Work Order`、`Material Request` 和 `Purchase Order`；
- 在 `process_simplification` 中提供一套共享的“物料覆盖计算”服务，快速开单、订单工作台和缺料采购页面必须调用同一口径；
- 共享服务返回全部物料覆盖行和过滤后的缺料行，不能只返回缺料行；
- 快速开单结果是检查时点的只读快照，不创建自定义库存或采购台账；
- 销售订单需要生产的行继续保存本次确认的 BOM 编号，避免默认 BOM 后续变化导致无提示的计划漂移；
- 任何创建采购申请的接口都必须重新读取标准单据、重新计算缺口并具备重复提交保护。

## 9. 边界场景

- 多个产品共享同一原料：按物料和仓库聚合采购缺口，同时保留每个产品的来源贡献；
- 同一物料分布在多个仓库：默认不跨仓合并，其他仓有库存时提示“可考虑调拨”，不自动当作可用；
- 半成品有库存：第一阶段沿用多级 BOM 展开，不做复杂的半成品库存抵扣；此类需求进入后续能力或标准生产计划；
- 替代料和替代 BOM：快速开单不自动选择，避免错误承诺；
- 批次、有效期和质检库存：不能确认可用时显示“无法判断”，引导标准流程；
- BOM 修改：预检与提交使用不同 BOM 或 BOM 内容发生实质变化时要求重新确认；
- 并发订单：库存或采购覆盖在提交前变化时要求重新确认；
- 已有 Work Order：快速开单阶段尚无销售订单行，不把未明确关联的生产任务直接视为本单覆盖；订单工作台按 Sales Order Item 重新计算；
- 销售订单取消或数量修改：后续采购需求不自动删除，工作台显示来源变化并交由用户处理标准单据；
- 采购单位与库存单位不同：快速开单展示库存单位缺口；正式采购阶段按照 ERPNext 转换因子和采购倍数处理。

## 10. 验收要点

- 产品需要生产但原料充足时，页面明确显示“需生产”且“缺料 0 项”，并能展开看到每项原料为何充足；
- 原料有账面库存但已被其他需求占用时，本单可用量正确减少；
- 同一订单多个产品共享原料时，采购汇总不会重复计算库存；
- 已转采购订单的采购申请数量不会与采购订单在途数量重复扣减；
- 晚于需求日期到货的采购订单不会消除当前缺口；
- 任一影响计算的订单内容变化后，明细立即标记过期；
- 提交前结果变化时不会创建销售订单，而是要求重新确认；
- 快速开单不会创建库存预留、生产任务、采购申请或采购订单；
- 缺料是警告，缺失必要 BOM 或仓库是阻断；
- 所有操作继续生成和使用 ERPNext 标准单据。

## 11. 非目标

本次不实现：

- 快速开单直接创建或提交采购订单；
- 自动选择供应商、替代料或替代 BOM；
- 自动跨仓调拨；
- 复杂半成品库存分配；
- 批次、序列号、委外、客户供料和产品组合；
- 自定义库存、生产或采购台账；
- 用一个跨单位的“总缺料数量”替代逐物料明细。
