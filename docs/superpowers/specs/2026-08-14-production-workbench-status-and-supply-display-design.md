# 生产工作台状态颜色与采购单展示设计

## 目标

让老板和车间负责人一眼区分“生产状态”和“交付风险”，并避免把未分配给本订单的采购单误解为本订单可开工的物料来源。

## 状态与风险分离

订单是否逾期继续由风险标签和卡片左侧边框表达；生产进行到哪一步由独立的生产状态标签表达。订单可以同时是“已逾期”和“可开工”，两者不能互相覆盖。

生产状态颜色固定为：

- `ready_to_start` 可开工：绿色。
- `in_production` 生产中、`partially_completed` 部分完工：蓝色。
- `unplanned` 待安排、物料摘要待到料：橙色。
- `material_shortage` 缺料、`master_data_blocked` 基础资料异常：红色。
- `awaiting_order_reservation` 待回补订单、`overplanned` 超计划生产及未知状态：灰色。

风险标签继续使用现有红、橙、蓝、绿口径。主卡片不得再把所有生产状态固定显示为灰色。

## 采购单条件展示

后端的库存和供应分配计算保持不变。前端按每张供应单据的 `allocated_qty` 和当前物料的 `current_gap_qty` 决定是否展示：

1. 当前物料由现货完全覆盖，即 `current_gap_qty == 0` 时，只显示实际分配给本需求的供应单据；因此 `allocated_qty == 0` 的采购申请或采购单隐藏。
2. 当前物料仍有即时缺口，即 `current_gap_qty > 0` 时，保留供应单据用于解释缺料原因：
   - `allocated_qty > 0` 显示“已分配给本单 N”。
   - `allocated_qty == 0` 显示“未分配给本单”。
   - `is_late == true` 同时显示“晚于本单交期”，不能只写含义不清的“迟于交期”。
3. 没有需要显示的供应单据时，不显示采购单明细行。物料已经现货齐套时，也不显示“尚未发起采购”；该提示只用于仍有采购缺口且没有供应单据的情况。

## 数据和安全边界

- 不修改按交期逐单分配库存、采购单和采购申请的后端算法。
- 不修改采购缺料大池汇总。
- 不创建或修改任何 ERPNext 单据。
- 只修改 `custom_apps/process_simplification` 前端渲染、样式、缓存版本和对应测试。
- 所有服务端文本继续经过 HTML 转义，单据链接继续使用标准路由。

## 测试与验收

- 可开工主状态标签渲染为绿色，逾期风险标签仍渲染为红色。
- 生产中为蓝色，待安排为橙色，缺料为红色。
- 现货齐套且采购单 `allocated_qty == 0` 时，HTML 中不出现该采购单和“晚于本单交期”。
- 仍有即时缺口时，未分配的晚到采购单继续显示，并同时包含“未分配给本单”和“晚于本单交期”。
- 分配给本订单的采购单显示“已分配给本单 N”，并保留采购单总未完成数量。
- 生产工作台全部现有前端测试和相关后端测试保持通过。

## 非目标

- 不改变订单交期、采购单交期或采购状态。
- 不将晚到采购自动改配给其他订单。
- 不增加手工隐藏、展开开关或新的持久化设置。
